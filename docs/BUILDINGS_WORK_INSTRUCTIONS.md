**実装状況（2026-09-24）：** 初版3施設、建設枠、月初完成、費用・返金、郡窓からの建設操作、収入・治安効果、現行セーブ形式での保存・復元を実装済み。`tests/base_map/godot/test_district_buildings.gd` で主要な動作を確認する。費用・効果は下記の暫定値で、長期試遊に基づく調整は今後の作業とする。

## 1. 目的と参考範囲

EU4 の「地域単位で建設枠を選び、金銭と時間を使って施設を建て、完成後に地域の生産・統治・軍事へ効果を与える」という判断を、本作の1546年開始・郡単位の内政に取り入れる。プレイヤーが郡ごとの見込み効果、費用、完成日、空き枠を比較して投資先を決められる状態を目標とする。

参考：[EU4 Wiki: Buildings](https://eu4.paradoxwikis.com/Buildings)。作成時点で指定ページの本文は取得できなかったため、同じ題材の[EU4中国語Wikiの建築ページ](https://www.eu4cn.com/wiki/Buildings)で確認できた建設枠、施設分類、改築、費用・建設期間の構造を参照した。同ページ自身が一部内容を旧版（1.28～1.30）と明記している。以下の数値や戦国日本向けの施設名は**本作独自の暫定設計**であり、EU4 の最新仕様や史実の建築費を示すものではない。

本手順は施設システムに限る。税制、食糧消費、騒乱、戦闘などの全体順序は[内政シミュレーション作業手順書](DOMESTIC_SIMULATION_WORK_INSTRUCTIONS.md)と整合させる。そこにある月次進行役・収支台帳がまだ未実装なら、本手順の工程1で施設に必要な最小限の月次処理と支払記録を先に作り、後で一本化する。

## 2. 現状と接続点

| 対象 | 現状 | 施設実装で必要な変更 |
|---|---|---|
| 郡 | `scripts/game/governance_registry.gd` に支配家、人口、農業・商工業開発度（各1～30）、基礎治安がある | 郡IDに紐づく完成施設と工事を持つ。地図形状や拠点IDに施設状態を持たせない |

| 日付 | `scripts/game/game_clock.gd` の `day_advanced` が日付を通知する | 月初に工事進行・完成判定を一度だけ実行。収入との前後関係を固定する |
| 技術 | `scripts/game/technology_tree.gd` に農業施設建築費を定額15下げる補助計算がある。商業ツリーは空 | 対象施設の支払額計算に接続。未実装の研究や EU4 の技術段階を前提条件にしない |
| セーブ | `scripts/game/game_session.gd` が郡状態・家の金銭などを JSON 保存、検証、復元する | 現行形式に施設・工事状態を追加し、保存・読込・再開を検証する |

1546年の郡と、1582年を対象に整備された城・集落・港の表示資料は年代が異なる。拠点の種類や位置を建設条件に使う場合は、開始時点に存在することと郡への帰属を別途確認する。初版の施設はこの未確定な立地データに依存させない。

## 3. 先に固定する仕様

### 3.1 建設単位と状態

1. 建設単位は**郡**。各郡に `buildings`（完成した施設IDと段階）と `construction`（工事中の施設ID、支払額、支払家ID、開始日、完成日）を持つ。初版は郡ごとに工事1件、同じ系統の施設は1件まで。
2. 施設の定義はデータ表に分離する。各行に安定した `id`、表示名、系統、段階、基礎費用、期間（月）、建設条件、効果種別と値、維持費を明記する。施設名をセーブ上の識別子にしない。
3. 空き枠を設ける。初版の暫定式は `min(6, 2 + floor((農業開発度 + 商工業開発度) / 10))`。新設は1枠を使い、同系列の改築は既存枠を使う。工事中の新設も枠を予約する。開発度が上がれば枠を再計算するが、既存施設が枠を超えても削除しない。超過中は新設不可とする。この式は EU4 の開発度式の移植ではなく、現行の2種類の開発度を使う本作の仮値。
4. 建設可否は単一の判定関数から返す。支配家、資金、枠、同系統の重複、工事中、施設固有の条件を確認し、UIに同じ不可理由を表示する。表示側だけで条件を推測しない。
5. 命令時に費用を確定して家の金銭から一度だけ差し引く。期間は暫定で暦月単位とし、開始日から指定月数後の日付以降、最初の月初を完成日とする。たとえば1546年1月1日の12か月工事は1547年1月1日に完成する。UIにもこの実際の完成日を示す。
6. 初版から取消を実装し、保存された実支払額を**支払家へ全額返す**。領有変更時は工事を取り消して元の支払家へ返し、完成施設は郡に残して新しい支配家の効果となる。領有変更処理がまだない段階では、この規則を将来の接続仕様として記録する。

### 3.2 初版の施設セット

最初は既存の計算に直接つながる施設に絞る。下表の費用・期間・効果は試遊用の仮値で、実装前にデータ表へ登録し、複数規模の家で調整する。維持費は初版では0に統一し、月次支出と不足処理が整ってから導入する。

| 系統 | 施設案 | 暫定費用 | 暫定期間 | 完成後の効果 | 主な確認点 |
|---|---|---:|---:|---|---|
| 農業 | 用水路 | 金銭100 | 12か月 | 当該郡の9月の兵糧収入 +10% | `共同管理法制定` の農業施設費 -15 を命令時の支払額に適用 |
| 商工業 | 市場 | 金銭100 | 12か月 | 当該郡の月次金銭収入 +10% | `楽市` 等の家単位補正と合成して二重計上しない |
| 統治 | 郡役所 | 金銭80 | 12か月 | 当該郡の表示治安 +5 | 基礎治安には書き込まず、支配家の技術補正と合わせて0～100へ収める |

収入効果は「基礎収入 × (1 + 郡施設補正) × 家の技術補正」を最後に1回丸める暫定順序とする。現行式の `BASE_VALUE + development`、人口係数、技術補正は維持する。郡役所は `security_for` 相当の表示・将来の騒乱判定の双方で同じ値を参照する。治安が今は収入へ影響しないことを説明文で隠さない。

次段階の候補は、農業・市場の上位施設、兵舎、築城、港湾施設。上位施設は同系統の既存枠を引き継ぎ、費用は差額方式を採るか新規費用方式を採るかを定義表と UI で明示する。兵舎は募兵・常備兵が動いてから、築城は包囲・占領が動いてから、港湾は1546年の海岸・港条件と海上機能が確認できてから効果を接続する。効果のない施設を先に建設可能にしない。

## 4. 実装手順

### 工程0：定義表と表示仕様を確定する

- [ ] 施設定義のスキーマ、初版3施設のID、単位、費用、期間、端数処理、枠計算を1つのデータ表に固定する。
- [ ] 建設前後の金銭・兵糧・治安の見込みを郡画面でどう表示するか決める。兵糧は「次の9月の年収差」、金銭は「月収差」と単位を区別する。
- [ ] `共同管理法制定` 未研究時・研究済み時の支払額、費用の下限、完了日の計算例を仕様例として残す。

**完了条件：** 任意の郡・家・日付について、候補の可否、支払額、完成日、収入差を表から再現できる。

### 工程1：状態、支払い、日付進行

- [ ] 郡施設を扱う独立した処理（例：`scripts/game/district_buildings.gd`）を追加し、`governance_registry.districts` の郡IDを参照する。初期化は新規ゲームとロードの両方で一度だけ行う。
- [ ] `can_build`、`start_construction`、`cancel_construction`、`advance_month` を用意する。命令と支払いは同一処理で行い、二重クリック・残高不足・枠不足で残高や状態を変更しない。
- [ ] `main_map.gd` から時計の月初通知へ接続し、工事完成と既存の金銭・兵糧収入の順序を固定する。同じ9月1日に完成した施設がその年の収穫へ効くかも明記する。
- [ ] 完成、取消、費用支払いを記録し、家残高の増減を追えるようにする。後続の共通収支台帳ができたらその記録経路へ統合する。

**完了条件：** 1郡で建設、12か月進行、完成、取消、再命令が動き、同じ月初に二度完成しない。

### 工程2：効果を既存計算へ接続する

- [ ] `district_economy.gd` の郡別 `income_for` から完成施設の補正を取得する。画面の見込み値もこの関数または同じ計算器を使う。
- [ ] `technology_tree.gd` の農業施設費補助を用水路の支払額へ接続する。効果計算では研究を再適用して収入を重複させない。
- [ ] 郡役所の治安加算を、現在の技術込み治安表示と後続の治安判定に共通の関数から適用する。施設完成時に郡の基礎治安を直接増やさない。
- [ ] 施設の追加・完成・取消・領有変更時に表示の見込みと候補可否を更新する。

**完了条件：** 建設中は数値が変わらず、完成後の対象郡だけに効果が出る。所有者が変われば家補正だけが新所有者のものへ切り替わる。

### 工程3：通常画面の操作

- [ ] `district_selection_info.gd` の郡選択から施設画面を開けるようにし、完成施設、使用枠、工事の残り期間を表示する。
- [ ] プレイヤーの支配郡だけに建設・取消操作を許す。他家や帰属未詳の郡では一覧と不可理由を表示する。
- [ ] 各候補に支払額、完成予定日、現在値→完成後見込み、建設できない理由を示す。建設成功・失敗時の通知を用意する。
- [ ] キーボード・マウス操作、画面幅の違い、スクロール中の郡選択との干渉を確認する。

**完了条件：** 通常起動だけで、郡選択から建設命令、完成確認、施設効果の比較まで行える。

### 工程4：セーブと回帰確認

- [ ] `game_session.gd` の現行セーブ形式に完成施設と工事状態を追加し、施設ID、段階、支払額、支払家ID、日付、郡IDの妥当性を検証する。現行形式での新規保存・読込だけを対象にし、旧形式の移行や互換性チェックは追加しない。
- [ ] 月途中、完成直前、完成直後の各状態で保存・終了・読込し、残高、工事、完成施設、次回収入が一致するか確認する。
- [ ] 少数の Godot テストで、費用不足、枠不足、重複、研究割引、9月完成時、取消、保存再開を通す。既存の時計・経済・技術・セーブのテストも回帰確認する。
- [ ] 小・中・大の家で5年間進め、回収期間と金銭残高を比較する。恒常的な資金不足や施設だけで収入が過大に増える場合は定義表の仮値を調整し、変更理由を残す。

**完了条件：** 同じ開始状態と命令なら、セーブを挟んでも完成月・家残高・次回収入が一致する。現在のセーブ形式で保存と読込が成功する。

## 5. 実装時に避ける不整合

- `house_resources` の金銭は家ごとの共有資源。郡の表示収入を直接書き換えて建設費を支払わない。
- 建設枠は現行の農業・商工業開発度から算出する。EU4 の税・生産・人的資源の3種の開発度をそのまま持ち込まない。
- 施設効果は完成済み状態から毎回算出する。完成時の一時加算だけにすると、ロードや所有者変更で効果が失われたり重複したりする。
- 1546年の施設初期配置を行う場合、史料にない全郡一律の「既存施設」は史実として扱わず、ゲーム用初期値と出典調査結果を分けて記録する。初版は空の施設状態から始める。
- 文書中の暫定費用と効果はテスト可能な初期値である。実装済みの仕様に変わった時点で表と画面説明を同時に更新する。
