# メモリ・CPU軽量化の実装と800%描画の検証

実施日：2026年10月2日。対象：[調査書](MEMORY_CPU_OPTIMIZATION_RESEARCH.md)に基づく現在の作業ツリー。

地形の区画化を追加実装した。[区画化・読み込み・解放・近景再利用の結果](TERRAIN_CHUNK_OPTIMIZATION_RESULTS.md)を参照。以下は追加実装前の記録であり、近景キャッシュの単位・上限は追加実装で変更した。

## 結果

画質を変えず、肖像の読み込み、静止中の再描画、HUD更新、地形生成、素材読み込み、診断処理を軽量化した。**800%で移動・回転し続ける場合の60fpsは未達成**である。静止中は60fpsに到達している。

変更前後のソース実行では、移動中の平均fpsが約2.0～2.4倍、回転中が約1.6～2.2倍になった。Windowsリリース実行ファイルでも同じ巡回を測定した。下表のソース実行とリリース実行は別の比較である。

メモリは、保持する肖像・同時読み込み・作業用配列・近景メッシュに上限を設けた。プロセス全体の使用量を小さい固定値に収めたものではない。変更前の同条件のWindowsメモリ計測がないため、総RAM／VRAMの削減率は断定しない。

## 実装内容

| 対象 | 変更 | 維持した内容 |
|---|---|---|
| 武将一覧 | 表示中の行と前後3行だけ肖像を非同期読み込み。画面外・一覧終了時は一覧側の参照を解放 | 1,598人の検索・並び順・選択・肖像の行高・詳細表示 |
| 肖像読み込み | 同時2件、推定24 MiBの専用予算。透明な仮アイコンで行高を固定 | 512×512の既存PNG、透過、詳細肖像の画質 |
| 地図マーカー | 毎フレームの再描画を廃止。カメラ・地形・表示情報の変更時に更新。部隊は別の描画ノードに分離 | 所属家の家紋、名称、遮蔽判定、部隊の移動・選択・外交色 |
| マーカー文字 | 文字幅を名称・サイズごとに再利用 | フォント、縁取り、文字サイズ、重なり回避の順序 |
| 地形への視線判定 | 標高の保守的な最大値から、地形に当たらない空間を飛ばす | 最後の当たり判定は従来と同じ三角形。山による遮蔽とクリック位置 |
| 近景地形 | 既存CPUジョブ管理に統合。ジョブは独立した不変データを保持。完成時に不要になった結果はGPUへ送らず破棄 | 2ワールド単位の頂点間隔、512×1,024の領域、継ぎ目の補間 |
| 地形配列の生成 | 高さを周囲1頂点を含む格子に一度だけ計算し、頂点と法線から共有 | 元の倍精度計算、頂点位置、法線、UV、三角形の接続 |
| 遠景・富士のメッシュ | 同じ頂点・法線のメッシュを制作時に保存。入力のハッシュが一致する場合に再利用 | 遠景16ワールド単位、富士0.25ワールド単位。頂点削減なし |
| 地形素材 | 同時2件、推定160 MiBの読み込み予算。現在・目標倍率から外れた未着手要求を取り下げる | 100／200／400／600／800%の専用素材とミップマップ |
| 上部HUD | 0.5秒ごとの集計を廃止。ゲーム内の変更イベントをまとめて次のフレームで更新 | 日付、内政、任命、部隊、外交、建築、研究、威信、保存状態の復帰 |
| 診断 | 毎フレームの停止監視は維持し、詳細スナップショットを基本100ms間隔に変更 | 非同期ログ、停止検出、操作履歴、回復、ローテーション |

近景地形のジョブ予約は9 MiB、既存CPUジョブ管理の総予約上限は16 MiB。近景メッシュのキャッシュは最大2件。作業用配列を生成後に保持し続けない。遠景頂点の別コピーも保持しない。

これらの予算は対象処理の推定値であり、ドライバー、全画像、フォント、描画先、ゲーム状態を含むプロセス全体のメモリ上限ではない。地図資産ストリームの予算、素材ストリームの予算、肖像の予算は別枠である。静止中も海面アニメーションを含む描画は継続する。

既存の武将肖像50枚の512×512化と、今後の保存解像度のAGENTS.md記載は先の作業で実施済み。今回さらに解像度や画像形式を変更していない。

## 測定条件

- Windows、Intel Core i7-12700F（12コア／20論理プロセッサ）、GeForce RTX 4060、NVIDIA 596.36。
- Godot 4.7.2、Compatibility／OpenGL、1920×1080、800%、視点角15度、VSync無効、最大60fps。
- 日付進行を止め、800%の素材と近景が読み込み済みの状態から開始。
- 移動は半径160ワールド単位の円を一周。回転は同じ中心で360度一周。各区間120フレームを集計。
- 経路はフレーム数に対して固定。実時間で同じ移動速度を保証する試験ではない。ゲーム日付進行・多数部隊の同時行動を含む最悪条件の保証でもない。
- 地点A＝(4480,5504)、B＝(4768,5440)、C＝(5500,4100)。生ログのラベルはそれぞれ `kinki`／`fuji`／`kanto`。ラベルは試験識別子で、行政区分の指定ではない。
- 初期版ベンチマークには最初の短いサンプルによる小さい上方偏りがあり、変更前の静止fpsが約61になる。最終版は最初の2フレームを集計から除外。移動時の改善幅は概数として扱う。

この巡回全体のWorking Set観測最大は **1458.0 MiB**、Private Commit観測最大は **3094.4 MiB**。Private Commitは実際にRAMに常駐する量と異なり、ドライバー関連の割り当ても含む。サンプリング間の瞬間的なピークは保証しない。Godotの最後のフレームにおけるテクスチャ推定値は最大約1056.0 MiB、バッファ推定値は最大約595.7 MiBだった。専用VRAMのドライバー実測値ではない。

実行ファイル自身から `--benchmark-map-800` を指定して計測し、外部スクリプトを無視するリリーステンプレートの挙動に依存しない。

## 画質・機能の検証

- 3地点の固定画面を変更前と変更後で比較。各1920×1080画像のRGBA値が完全一致し、差分画素数はすべて0。比較結果は `builds/performance_800/pixel_comparison.json`。全倍率・全視点の画素一致を保証するものではない。
- 264,307頂点について、最適化前の計算式と最適化後の頂点・法線が一致。三角形のインデックスも一致。入力ハッシュが変わった事前生成メッシュを拒否することを確認。
- 480本の視線について、加速あり／なしの地形当たり判定が一致。最大のワールド座標差0。
- 視点角・画面位置・ズームの検証はPASS。画面への投影誤差最大約0.00275px、ズームのアンカー誤差最大約0.00744px。
- 静止中60フレームにマーカーとHUDが追加更新されず、操作・ゲームイベント・史跡表示切替で更新されることを確認。
- 肖像一覧の全1,598人を保ち、スクロール・表示中の画像到着・読み込み上限・一覧終了時の解放を確認。既存の採用肖像50人（5組）の表示テストもすべてPASS。
- 回転操作、近景切替、600／800%素材、富士の詳細と継ぎ目、郡奉行所、部隊の出陣・移動・帰還・現形式の保存、診断ログの停止・回復・ローテーションはPASS。
- 単独のTime HUDテストの機能検証は0 failures。ただし終了時にObjectDB／Resourceの残存警告が出たため、このテストをエラーなしの終了とは扱わない。
- Windowsリリースを書き出し、通常のタイトル画面起動も180フレーム実行して終了コード0を確認。`normal_release_launch.log` にエラーなし。

部隊の既存テストは3D地図に対応した画面座標変換に修正し、部隊機能の検証では平面表示を使用した。立体地図のクリックと遮蔽は別の視点・視線テストで確認した。ゲームの保存形式は変更していない。

## 60fpsに向けて残る作業

1. 地図の2D描画先に送る六角形、境界線、文字などの描画コマンドとGPU転送を削減する。六角形・境界線の単純な描画ノード分割や広い範囲のキャッシュは、今回の試験では安定した改善がなく、GPUバッファ保持を増やす場合もあったため採用しなかった。
2. 現在1968×4096になる地図描画先を、同じ画素密度のまま必要な投影範囲へ絞る。低い視点、回転、地形による遮蔽、画面外の遠景について追加の品質検証が必要。
3. 海面アニメーションと静的地図を分離し、地図全体の再描画を抑える。海面の見え方と合成結果の維持が必要。
4. 富士の詳細メッシュの地域外での遅延読み込み・解放、地形データの分割を検討する。現在は事前生成の再利用まで実施し、富士詳細の起動時保持は維持している。

単純なLOD削減、地図の解像度低下、境界線・名称・陰影・海面の削除は行っていない。重い地点の回転p95は16.67msを大きく超えるため、平均fpsだけで60fps達成とは判断できない。

## 再生成・再測定

標高や地形メタデータを変更した場合は次を実行する。ハッシュ不一致の場合、実行時は従来の地形生成・視線判定に戻るため表示品質は維持されるが、高速化の効果は失われる。地形計算式を変更する場合はメッシュの形式バージョンも更新し、再生成する。

```powershell
python tools/build_terrain_ray_bounds.py
godot_console --headless --path . --script tools/godot/build_terrain_meshes.gd
python tools/export_windows_release.py
python tools/qa/run_gpu_check.py tests/base_map/godot/benchmark_map_800.gd repeat_release --release --stage=repeat_release --frames=120
```

通常の起動には試験用引数を付けない。最終成果物は `builds/windows-latest/MyWorldsOnFreedom.exe` と同じ場所のPCK。出力・実行ログ・Windowsメモリ／CPUサンプルは `builds/performance_800` に保存する。
