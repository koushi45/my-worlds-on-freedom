# 日本基盤ポリゴン起点の再構築作業指示書

## 1. 目的

日本マップに関するすべての地理データを、唯一の日本陸地基盤ポリゴンから一方向に生成する。全国・地方・狭域の各マップ、海岸線、地形、クリック判定、政治境界で別々の海岸形状を作らない。

基盤ポリゴンが承認されるまでは、国境、郡境、地形、植生、河川、道路、城、クリック領域、LOD画像を実装しない。

## 2. 非交渉ルール

1. 日本陸地の正本は1ファイル、1レイヤー、1バージョンに限定する。
2. 正本はラスター画像ではなく、妥当な `MultiPolygon` ベクターとする。
3. 正本を簡略化、平滑化、穴埋め、島の削除で上書きしない。
4. 表示向け加工は必ず派生データとして生成する。
5. 海岸線は正本ポリゴンの外周からのみ生成する。画像から再抽出しない。
6. 湖岸は陸地外周と分離し、湖レイヤーとして管理する。
7. 政治境界は陸地正本の内部へクリップし、海岸線を政治境界として重複保持しない。
8. 真上向き座標を正本とし、斜め表示は実行時の表示変換だけで行う。
9. 生成処理は入力ハッシュと設定が同じなら、毎回同じ成果物を生成する。
10. 各工程の検証ゲートを通過するまで次工程へ進まない。

## 3. ディレクトリと成果物

```text
data/
  sources/                         取得した原本。改変禁止
  master/
    japan_land_master.gpkg         唯一の基盤ポリゴン
    japan_land_master.geojson      目視・交換用ミラー
    japan_land_master_manifest.json
  derived/
    coastline/
    land_masks/
    lod/
    political/
    terrain/
assets/
  map/
tools/
  base_map/
tests/
  base_map/
builds/
  qa/
```

正本はGeoPackageの `japan_land` レイヤーとする。GeoJSONは交換・レビュー用であり、GeoPackageから毎回生成する。ゲーム用8192座標データも正本ではなく派生物とする。

## 4. フェーズA：採用データの確定

### A-1. 候補評価

候補ごとに以下を記録する。

- データ名、配布元、取得URL、取得日、版番号
- 商用利用、改変、再配布、表示義務、継承義務
- 座標参照系、縮尺、測地精度、更新日
- 日本本土、北海道、沖縄、離島の収録状況
- 海岸の細かさ、自己交差、欠損、重複
- ゲームへ同梱可能か

ライセンス本文と取得ファイルのSHA-256を保存する。利用条件が不明な候補は採用しない。

### A-2. 採用判断

候補の比較画像を同一座標・同一縮尺で作成し、少なくとも北海道、東京湾、伊勢湾、大阪湾、瀬戸内海、九州西岸、南西諸島を確認する。採用データと必要な修正方針をユーザーが明示承認した後だけ次へ進む。

## 5. フェーズB：基盤ポリゴンの作成

### B-1. 正本仕様

- 保存形式：GeoPackage
- レイヤー名：`japan_land`
- ジオメトリ型：`MultiPolygon`
- 地理座標の基準：採用原本のCRSを保持し、CRSを必ずメタデータへ記録
- ゲーム標準投影：範囲を固定した真上向き8192×8192座標への決定論的変換
- 外周：海岸線
- 内周：原本上の穴。湖として扱うものは湖IDと対応付ける
- 島：正本では面積によって削除しない
- 座標精度：原本より粗く丸めない

### B-2. 許可する修復

- 自己交差の修復
- 重複頂点と長さ0の辺の除去
- 同一島の重複ポリゴンの統合
- 明白なリング方向の正規化

修復前後の面積差、頂点数差、変更箇所をレポートする。見栄えを目的とした平滑化や簡略化は正本に適用しない。

### B-3. 必須属性

`japan_land`には少なくとも以下を持たせる。

| 属性 | 内容 |
|---|---|
| `feature_id` | 永続ID |
| `part_class` | mainland / island |
| `source_id` | 原本側ID |
| `source_version` | 原本の版 |
| `edit_status` | unchanged / repaired / manual |
| `edit_note` | 修正理由 |

マニフェストにはファイルハッシュ、CRS、範囲、面積、島数、内周数、頂点数、生成ツール版を記録する。

## 6. 検証ゲート1：基盤ポリゴン承認

自動検査で以下をすべて満たす。

- ジオメトリが妥当
- 空ジオメトリ、自己交差、重複面、NaN座標が0件
- 全ポリゴンが日本用の想定範囲内
- ポリゴン同士の意図しない重なりが0
- 修復前後の面積差が設定した許容値以内
- GeoPackageとGeoJSONミラーの面積・構成数が一致
- 再生成前後のSHA-256が一致

目視検査用に以下を生成する。

- 全国全景
- 地方別拡大
- 海岸頂点表示
- 原本との差分ヒートマップ
- 修復箇所一覧

ユーザーの承認を `japan_land_master_manifest.json` に版番号とともに記録する。承認前に派生レイヤーを作らない。

## 7. フェーズC：海岸線と陸地マスク

正本の外周リングから海岸線を生成する。海岸線の元座標を別途推定しない。

```text
japan_land_master.gpkg
  ├─ coastline_master.gpkg
  ├─ land_mask_8192.png
  └─ land_master_8192.json
```

海岸線とマスクは同じ変換関数・同じ座標範囲を使用する。通常表示の海岸線と選択表示の海岸線は、同じ海岸線IDと同じ点列を参照する。

## 8. フェーズD：LOD

5段階のLODは基盤ポリゴンから派生させる。各LODは別々の画像から輪郭抽出しない。

1. 正本を目的の平面座標へ変換
2. トポロジーを維持した簡略化
3. 同じLODポリゴンから陸地塗りと海岸線を生成
4. 表示海岸線と選択海岸線で同一の点列を共有

小島を広域で非表示にする場合も、正本から削除せずLODの表示フラグだけを変更する。LOD切替点で海岸線が移動しないことを差分試験する。

## 9. フェーズE：地図画像と地形

全国、地方、狭域の画像は共通のLOD陸地ポリゴンを塗りつぶして生成する。

- 海陸判定を色の閾値から推定しない
- ModeFilterなど海岸位置を動かす処理を適用しない
- アンチエイリアスは境界位置を変えないカバレッジ処理に限定
- 地形、植生、土、雪は陸地マスク内へクリップ
- 海と湖を別IDで保持
- タイル境界でも同じグローバル座標を使用

最終的に専用海岸線ベクターをテクスチャより上へ描画し、サブピクセル差を隠さず同じ中心線として表示する。

## 10. フェーズF：政治境界とクリック判定

政治領域は必ず基盤陸地との積集合で作成する。

```text
political_region = historical_region ∩ japan_land_master
```

- 隣接地域が共有する辺だけを政治境界として保存
- 海岸部分は海岸線IDへの参照として保存
- 国選択表示は共有政治境界＋参照海岸線で構成
- クリックマスクは判定専用で描画しない
- クリックマスクから表示線を逆生成しない
- 未確定領域は推測で埋めず、状態を明記

全政治領域の和集合と対象陸地との差、地域間の重複、隙間を自動検査する。

## 11. フェーズG：その他の派生レイヤー

河川、湖、道路、城、文化、人口、地形分類は基盤ポリゴン承認後に追加する。

- 河川と道路は同じ地理座標からゲーム座標へ変換
- 城は地理座標を正本とし、表示用座標を別保存しない
- 陸上要素は基盤陸地外に出ていないか検査
- 地形分類は基盤マスクを共有
- 斜め表示用にデータを変形保存しない

## 12. テスト要件

最低限、次のテストを自動化する。

- 基盤ポリゴンの妥当性とハッシュ固定
- CRSと8192座標の往復変換
- LODごとの海岸線と陸地外周の距離が0
- 通常海岸線と選択海岸線の点列IDが同一
- 全国・地方・狭域の重複範囲で陸地マスクが一致
- タイル継ぎ目の不連続が0
- 真上表示と斜め表示の逆変換
- クリック対象と表示境界の一致
- 画面外タイルの非描画
- Windows、Android、iOS、Web向け読み込み互換性

## 13. 実施順序と停止条件

```text
データ候補・ライセンス確認
  → 基盤ポリゴン作成
  → 検証ゲート1・ユーザー承認
  → 海岸線・陸地マスク
  → LOD
  → 地図画像・地形
  → 政治境界・クリック判定
  → その他レイヤー
  → プラットフォームビルド
```

次の場合は作業を停止し、推測で進めない。

- 原本またはライセンスが確定していない
- 正本ポリゴンに自己交差や欠損が残る
- 原本と修復後の面積差が許容値を超える
- 海岸線と陸地マスクが同じ正本から生成されていない
- LOD間またはタイル間で海岸位置が変わる
- ユーザーによる基盤ポリゴン承認が未完了

## 14. 最初の次作業

次回はフェーズAだけを実施する。商用利用条件と精度を確認した日本陸地ポリゴン候補を比較し、基盤として採用する原本を決定する。承認前にマップ画像やゲーム機能を作らない。
