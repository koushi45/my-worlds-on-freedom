# CPU行動の実装と確認

2026年10月3日実装。領地を持つ他家は、日付の進行に合わせて外交・軍事・内政・人事・研究を判断する。プレイヤーの家にはCPU命令を出さない。判断方針は [CPU大名家の行動設計](CPU_BEHAVIOR_DESIGN.md) を参照する。

## 必須行動の実装

| 条件 | 実際の行動 |
| --- | --- |
| 宣戦された、または領地への攻撃で戦争が始まった | 防衛目的を設定し、直接の同盟国へ参戦を要請する。CPU同盟国は停戦等の条件を確認して参戦し、兵・武将・兵糧が揃えば出陣・進軍する |
| 到達できる弱い家がある | 相手単独の戦力が自家の80%以下で、防衛同盟込みでも自家が1.25倍以上なら、出陣元と補給を確認して宣戦・侵攻する |
| 強い近隣家に脅かされる弱い家 | 自家より強い保護者候補を選び、使節、予算に応じた贈物、条件成立後の同盟提案を行う |

敵味方はプレイヤーを特別扱いせずに評価する。兵や武将のいない家、兵糧の足りない家は、資源を増やして出陣するような特例を使わない。新規ゲームの初期腰兵糧は、従来プレイヤーだけに与えていた同じ計算を全家へ適用した。

## 同盟参戦と操作

防衛側の直接の同盟国だけに要請する。同盟の同盟への自動連鎖は行わない。攻撃側とも同盟しているCPU家は、防衛義務を優先して攻撃側との同盟を破棄する。停戦中の場合は要請を保存して待機し、停戦終了後に参戦する。

プレイヤーへの要請は画面右側の「同盟国から参戦要請」ボタンから開く。外交画面で要請元の家を選び、「同盟国の防衛戦争に参戦する」または「参戦を辞退する」を押す。プレイヤーが防衛側の場合も同盟国への要請が発生し、外交画面から再要請できる。

主たる攻撃側と防衛側が停戦すると、その戦争だけに参加していた同盟国の敵対も終了し、停戦期間を設定する。別の戦争で敵対が継続する場合は、その関係を維持する。シナリオ初期の敵対は開始者を推測せずに扱い、実際の攻撃または参戦要請で戦争の立場を記録する。

## 部隊命令と資源

出陣、移動、経路指定、停止、方向変更、帰郡に家ごとの共通命令を追加した。プレイヤーのUIは自家限定のままとし、CPU部隊の出陣や帰郡でプレイヤーの選択部隊を変更しない。

CPUは自領・同盟領付近の敵部隊を優先し、それ以外では到達可能な敵の奉行所を攻略する。兵のいる郡へ出陣武将を配置し、大将と最大2人の副将を選ぶ。軍馬・鉄砲は在庫が足りる場合だけ消費して装備する。六角形の通行制限と道路による所要日数を使い、第三国の奉行所や施設を経路から避ける。

出陣割合は資源と守備余力に応じて50%または25%を選び、郡の兵力上限の30%を守備用に残す。1家につき1日1部隊まで出陣し、領地数に応じて同時運用を2から12部隊に抑える。兵数が出陣時の40%未満、または腰兵糧が帰郡見込み日数と余裕10日に達したら帰郡する。出陣元を失った場合は、到達できる別の自領へ帰る。

## 内政と判断処理

月ごとに開発担当、役職、統治担当、忠誠不足の武将の俸禄、施設、荒廃修復、基盤整備、研究を見直す。2か月分の俸禄を残した予算で投資する。戦時には砦と兵舎、兵糧不足時には農業施設を優先する。俸禄不足時の建築中止や、戦時に必要な砦の枠を確保するための寺社撤去も共通処理を使う。

戦略評価は原則7日ごと、部隊命令は毎日行う。全国の経路探索が一度に集中しないよう、評価日と探索順を分散し、新規探索に日ごとの件数・時間予算を設ける。探索を翌日へ回した場合は到達不能として保存せず、次の日に再評価する。地形の連結範囲、郡間の距離、家ごとの経路を再利用し、領主・外交・道路が変わったら該当する結果を破棄する。

## 日付進行と処理待ち

日付を先に進めて全家を一括実行する方式を廃止した。その日の開始時に建築、経済、人事、補給、郡の兵力、外交、CPU判断の仕事を登録する。プレイヤーの操作と描画は継続し、仕事をフレーム間で分割して実行する。Godotのシーンとゲーム状態への変更はメインスレッドで行う協調実行で、複数スレッドから同じ状態を直接変更しない。

CPU処理の1フレームの目標予算は3ms。家の人事、郡ごとの内政、研究、戦略、部隊命令を別の仕事にする。個別の共通命令や経路探索は原子的に完了させるため、単独の仕事が予算を超える場合はある。月次判断は家の並びに応じて1〜28日に分散し、月初に全家の内政を集中させない。月初の徴収・俸禄などの発生日は維持する。

軍隊の移動・戦闘は時計が受理した当日分の時間だけを使う。当日の時間を消費しても未処理の仕事があれば同じ日付で待機する。仕事とHUD更新が終わった後にも描画フレームを挟み、完了した日から1日だけ進む。待機中の実時間を繰り越す追いつき処理は行わない。速度変更、一時停止、メニューからの再開もこの順序を守る。

## 保存と読込

保存形式は19。CPUの目的、対象家、次回判断日、部隊任務、出陣時兵数、帰郡状態、判断ログ、戦争参加者、参戦待機・辞退を保存する。未知の家や不正な日付・兵数を検証して拒否し、当日の開始済み状態と未処理の仕事も保存し、読込時は残りから再開する。参戦や費用を再実行しない。旧形式の移行は追加していない。

読込では、地図表示を初期化してからカメラを復元するよう順序も修正した。

## 確認方法

- `test_day_barrier.gd`：処理待機中の日付固定、操作受付、移動時間の上限、途中セーブと再開、停止、描画待ち、翌日への単独進行を確認する。
- `test_cpu_controller.gd`：防衛・同盟援軍の実出陣と進軍、資源消費、弱い家への侵攻、強い家との同盟準備・成立、強い同盟による抑止、二重同盟の処理、停戦終了後の参戦、プレイヤーの参戦応答、撤退、建築・研究、現在の保存形式の保存・読込を確認する。
- `test_cpu_simulation.gd`：初期シナリオの全国CPUを35日進め、実出陣・移動、毎週の保存検証、資源の非負、プレイヤーをCPUが操作しないことを確認する。
- `test_army_campaign.gd`：従来の出陣・六角形移動・帰郡・戦闘・保存を確認する。
- `test_start_session.gd`：タイトル、メニュー、保存・読込、独立勢力を含む再開を確認する。
- `test_diplomacy.gd`：既存の外交条件、費用、待機期間、同盟、宣戦、停戦、保存を確認する。

各テストは `godot_console --headless --path . --script tests/base_map/godot/テスト名.gd` で実行する。UI撮影は `godot_console --path . --script tests/base_map/godot/test_cpu_controller.gd -- --capture` とし、`builds/qa/cpu_diplomacy.png` に出力する。

Windowsリリース版は `python tools/export_windows_release.py` で `builds/windows-latest/MyWorldsOnFreedom.exe` と同フォルダのPCKへ書き出す。

## 確認結果

必須3行動を含むCPUシナリオ、全国35日進行、既存の出陣、タイトルと保存・読込、外交の検証はすべて失敗0件。参戦要請画面を通常の描画で撮影し、要請の説明と参戦・辞退ボタンを確認した。

Windowsリリース版の書き出しは成功し、エクスポートログのエラーは0件。書き出したEXEをOpenGLで実際に起動し、初期シナリオの149家のCPUを35日進め、実部隊の出陣・進軍と保存・読込を確認した。配布版の確認結果は `builds/qa/cpu_release_result.json` に保存している。

配布版の確認を再実行する場合は `MyWorldsOnFreedom.exe -- --cpu-release-check` を使用する。確認専用の新規ゲームと保存先で動作し、結果を `user://qa_cpu_release/result.json` に出力して終了する。通常の起動ではこの確認処理を実行しない。
