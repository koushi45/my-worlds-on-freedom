# 九州・画像変形と旧国境界のレビュー

## 状態と対象

九州本島のみの未承認候補。筑前・筑後・豊前・豊後・肥前・肥後・日向・薩摩・大隅の9国、15本の共有国境線、9区間の海岸線参照を作成した。
対馬・壱岐・五島・天草など、別ポリゴンの島の所属はこの候補では未確定。全国版および製品用ゲームシーンには組み込んでいない。

## 今回実際に変形したもの

- 入力はユーザー提供画像を保存した `data/work/political/coast_alignment_v2/source_rgba.png`。透明部分のRGBノイズを無視し、線の濃度を表すアルファを使用する。
- 九州の岬・湾・海峡の62対応点と、外側の補助点から150三角形の局所区分線形変換を作成した。補助点は地理的な対応点ではない。
- **この変換で画像の全画素を実際に再サンプリング**した。内陸の国境線も同時に変形する。基盤陸地・基盤海岸線・入力画像ファイルは書き換えない。
- 国境線は画像内で手動指定した経路の近傍だけを探索し、黒い実線の中央付近を補助トレースする。線を同じメッシュで変形する際は三角形の辺で分割するので、画像とベクターで別の変形にはならない。
- 地理資料ではなく低解像度画像からの読み取りであり、全線は `probable / pending` とする。

## 国境と海岸線の分離

- 国境線の海上にはみ出した端だけを、基盤陸地との積集合で切り落とす。内陸点を一括スナップしない。端点の調整量はレポートへ記録する。
- 基盤の九州本島ポリゴンと15共有国境線から閉領域を構築し、改めて基盤陸地と積集合を取る。微小隙間を所有国へ割り当てる処理はない。
- 海岸は `jp-coast-e4e520d341c65420` の正本点列と始終点の距離参照を使う。通常表示も選択表示も同じ正本を参照し、クリックポリゴンから表示線を生成しない。
- クリック用ポリゴンは判定専用。別レイヤーに見える選択表示は対象国の共有国境＋正本海岸の参照区間で構成する。

## 検証と精度の読み方

正本・入力画像のSHA-256不変、9領域の妥当性、隙間・重複、各国と共有線の一致、海岸参照の全周被覆、余分な閉ループ、変形三角形の反転・重複、逆変換、画像の逆写像再サンプリングを検査する。幾何の誤差許容は面積・長さともゲーム単位で `1e-6` 以下とする。

対応点を1点ずつ除外した位置予測誤差は中央値約22.36、95パーセンタイル約53.07ゲームpx。これは対応点間での位置合わせの不確かさであり、史実精度ではない。実線への距離も中心線精度を保証しない。補間に使った点だけを測定して「位置合わせ誤差0」とは扱わない。

画像とNatural Earthでは海岸の細かさが異なるため、変形画像の海岸は全周完全一致ではない。特に九州西岸の湾や半島は比較画像で要確認。表示用の海岸線は、画像側を再トレースせず正本をそのまま使う。

## 再生成・確認

プロジェクトルートで実行する。

```powershell
python tools/build_kyushu_registration.py
python tools/verify_kyushu_registration.py
```

Godotで `tools/review/kyushu_registration.tscn` を開いて「現在のシーンを実行（F6）」する。クリックで国名と選択線、Wで変形画像、Bで抽出国境の表示を切り替える。ドラッグで移動、ホイールで拡縮、Fで全体表示に戻る。

レビューシーンは `tools/` に配置し、全エクスポート設定で `tools/*` と `data/work/*` を除外した。承認後の正本化と製品シーンへの接続は別工程とする。
