# 1582年の城・主要集落・港を配置する作業手順書

作成日：2026-09-11  
対象時点：**1582年、本能寺の変の直前**（既存道路レイヤーと共通）  
状態：配置機能と全国250拠点版を実装済み。

更新方針：後続のユーザー指定に従い、地方別比率を維持して約250拠点を選定する。同じ都市・城下の城・町・港は構成要素として統合し、複数拠点として水増ししない。初期手順の件数・分割方針より、この指定を優先する。配分・統合と推定の扱いは [全国250拠点版](settlements/EXPANSION_250.md) を参照。

## 1. 目的と成果

城・主要集落・港を史料に基づいて選び、名前付きで地図に配置する。次工程で、史料で確認できる道とゲーム用の推定連絡路をつなぐための、共通の拠点台帳を作る。

今回の配置工程では、拠点の名称、種類、対象時点の状態、位置、出典、採用理由を確定できる範囲で記録する。道路の自動生成や移動時間の設定は次工程で行う。ゲーム用の道を補完する方針は、史料のない城や集落を実在地点として創作する根拠にはしない。

成果物は以下の5点とする。

1. 城・集落・港の編集用台帳と、出典ごとの確認記録。
2. 採用・保留・除外と、その理由を追跡できる一覧。
3. 名前付きの独立拠点レイヤー。平面・立体表示、種類別表示、地点への移動に対応。
4. 地域別の確認画像と、位置・年代・重複・表示の検査結果。
5. 既存道路の通過点と、新しい拠点IDの対応表。

## 2. 作業範囲と順序

全国で同じ台帳・判断基準を使う。最初は現在の追加回廊を検証しやすい**日向・大隅・薩摩**から着手し、九州の残る旧国、続いて全国へ地域単位で展開する。拠点数の目標を先に決めて史料のない地点で埋めない。

各地域では「主要拠点を一巡 → 地域内の補助拠点を追加 → 表示と重複を確認」の順に作業する。旧国ごとの登録件数が同数になる必要はない。空白地域は調査不足か、選定基準に合う地点が見つからなかったかを記録する。

地理的範囲は既存基礎地図の設定に従う。未収録の島や北海道の地域は、未調査と拠点不存在を区別する。南西諸島など既存の対象外範囲を、本工程だけで拡張しない。

## 3. 採用対象の定義

| 種類 | 選定対象 | 確認する事項 |
|---|---|---|
| 城 | 領域支配の中心城、地域の支城、交通・軍事上重要な山城や館 | 対象時点の利用、所在、同名城、移転・廃城、当時の呼称 |
| 主要集落 | 城下、地域支配の中心、市場町、交易集落、交通上重要な寺社門前など | 存在だけでなく、主要拠点として選ぶ機能の根拠 |
| 港 | 海港、河口港、河川・湖の船着場のうち、地域交通・交易に関係するもの | 当時の利用、水域の種類、港域と上陸地点、後代の移転や埋立て |

城と集落が同じ地域にある場合、史跡と集落を区別できれば別IDを持たせ、同じ拠点群として関連付ける。全国表示では拠点群をまとめて表示し、拡大時に個別地点を出す。港町も集落と港の位置・役割を分ける。位置を分ける根拠がなければ、無理に複数の点を置かず、代表点に複数の役割を記録する。

峠、渡し、道路の分岐、道の曲がりを表す補助点は交通用通過点として別管理する。これらを集落の件数へ混ぜない。

### 「主要」の選び方

以下の役割のうち、資料で確認できるものを採用理由にする。人口や石高が不明な地点に推測の数値を与えない。

- 広域の政治・軍事の中心。
- 地域の行政・軍事の中心、または重要な支城。
- 市・交易・生産物集散の中心。
- 陸路・水路の結節点、主要な港や渡しに付随する集落。
- 周辺拠点との移動を考えるうえで重要で、存在と役割に根拠がある地点。

表示優先度は「広域中心／地域中心／補助拠点」の3段階とし、歴史的な確かさとは別の属性にする。城だけを増やして集落・港の調査を省略しない。

## 4. 資料を調べる手順

1. 自治体史、教育委員会・博物館の解説、遺跡報告、文化財一覧から候補を集める。
2. 候補ごとに発掘調査報告、城館調査、集落・港湾史、当時の文書やその研究へ進む。
3. 「存在」「対象時点の利用」「名称」「位置」「機能」を別の主張として記録し、それぞれを裏付けるページ・図・記述へ結び付ける。
4. 資料間で食い違う場合は両説と判断理由を記録する。同じ原典を引用した複数ページを、独立した複数証拠として数えない。
5. 江戸絵図や近代地図は地名・位置の手掛かりとして使い、1582年へ継続していたと判断する根拠を追加確認する。

### 調査入口

以下は資料を探す入口であり、登録する個々の地点の証拠そのものではない。台帳には入口URLだけでなく、実際に読んだ資料・該当箇所を記録する。

| 入口 | 用途 |
|---|---|
| [全国遺跡報告総覧](https://sitereports.nabunken.go.jp/ja) | 城館・集落遺跡などの調査報告を探す |
| [文化遺産オンライン](https://bunka.nii.ac.jp/) | 文化財の名称、所在、解説から関連資料へ進む |
| [東京大学史料編纂所・データベース検索](https://www.hi.u-tokyo.ac.jp/db/) | 年代・地名・文書の所在を調べる |
| 自治体の文化財・郷土史・博物館ページ | 地域調査、移転・改称、港や集落の沿革を確認する |
| [地理院地図](https://maps.gsi.go.jp/) | 現代の地形・地名・位置を照合する。1582年の存在証明には使わない |

出典台帳には、書名・発行者・発行年・URL・閲覧日・ページ／図番号・確認内容・閲覧範囲を保存する。PDFの紙面ページとファイル上のページが違う場合は両方を書く。検索結果だけを読んだものは `index_only`、本文確認済みは `full_text`、必要箇所だけ確認したものは `partial` とする。取得失敗や未閲覧も記録する。

画像・本文を保存する場合は資料ごとの利用条件と帰属情報を記録し、配布可能なものだけを配布物へ含める。原文の大量転載ではなく、確認した事実と出典箇所を台帳へ記述する。

## 5. 年代と名称を判定する

対象年だけでなく「本能寺の変の直前」を基準にする。同年後半の築城・廃城・移転・改称・占領を混在させない。史料の日付は暦を明示して原表記を保持し、換算日を使う場合は換算方法も記録する。

| 対象時点の判定 | 記録と表示 |
|---|---|
| 存在・利用を裏付ける資料がある | 対象時点の拠点として採用可能 |
| 前後の資料から継続利用を推定できる | 推定理由と反証確認を記録し、推定であることを残して採用可能 |
| 「中世」「戦国期」など時期が広く、1582年の状態が絞れない | 年代未確認。調査用表示に置き、通常表示への採用は理由を明示する |
| 1582年より後に成立、または対象時点で廃絶を確認 | 活動中の拠点から除外。調査台帳には残す |

史跡の存在と、対象時点に活動する拠点だったことを分ける。築城年が早いだけで1582年の利用を確定しない。現代の天守・資料館・市役所の位置や名称を、当時の城・城下のものとして転用しない。

表示名は対象時点の呼称を優先する。呼称が不明な場合は、確認できる地域名に「付近」を付けるなどして、名称の判断理由を記録する。現代名、別名、読みは検索用の別属性へ保存する。所有者・城主は別の年代情報とし、不明でも位置登録を止めず、旧国名や近世藩名から自動推定しない。

## 6. 位置を決める

1. 調査報告の位置図・遺構図、公的な史跡位置、研究上の比定地を探す。
2. 城は対象時点の主郭・館など確認できる場所、集落は当時の中心域、港は当時の港域・船着場の比定地を代表点にする。
3. 場所が広域までしか絞れなければ地域代表点として記録する。地点を絞れなければ座標を空欄にし、調査一覧へ残す。
4. 古地図を位置合わせする場合は、使用した基準点、変換方法、残差、時代差を記録する。現代河川・海岸だけを一致させて正確と判断しない。
5. 座標は WGS84 の `[経度, 緯度]` で保存する。原資料の測地系と変換方法も残す。住所検索の代表点を遺跡の測量座標として扱わない。
6. 位置の状態を `site_identified`（所在地を特定）、`area_estimate`（地域内の推定）、`unlocated`（未特定）で区別する。誤差の数値に根拠がなければ `null` とし、未知を0mにしない。

港については、現代の港湾施設ではなく当時の港域を調べる。旧海岸、埋立地、河口移動を確認し、「港域の代表点」「陸路の到着点」「航路の接続点」を同一と決めつけない。海港・河港・湖港を区別する。

### 基礎地図との整合

既存の `data/base/japan_land.gpkg` と `japan_land_manifest.json` を基礎とし、地図の投影・縮尺・オフセットはマニフェストの `game_transform` を利用する。画面位置から逆算した座標を正本にしない。

基礎陸地は広域向けに簡略化されているため、史料の位置が陸地外や現代の水面上に出ても、直ちに地点が誤りとはしない。座標誤り、基礎地図の省略、海岸・河道の時代差を分けて調べる。

自動的に陸地へ吸着させず、原位置を保持する。表示上ずらす必要がある場合は `display_anchor` と移動理由を別記し、原位置との対応を引出線で示す。表示用位置を道路の接続位置に流用しない。基礎陸地や水系を拠点に合わせて変更しない。

以下は**配置工程で新設する仕様案**。現在の実装済みファイルと混同しない。

| 保存先 | 内容 |
|---|---|
| `data/editorial/settlements/settlements_1582.json` | 編集正本。保留・除外も含む全候補 |
| `data/editorial/settlements/sources.json` | 出典と、確認した主張・箇所 |
| `data/editorial/settlements/road_anchor_links.json` | 既存道路通過点との対応・不一致の理由 |
| `data/derived/settlements/settlements_1582.json` | 正本から再生成するゲーム用座標・表示属性 |

| `scripts/map/settlement_layer.gd` | 名前付き拠点の描画・選択 |
| `docs/settlements/` | 地域別の調査記録・保留理由・検証結果 |

### 地点ごとの必須項目

| 項目 | 記録内容 |
|---|---|
| `id` | 改名・座標修正でも変えない一意ID。並び順や現在の城主を含めない |
| `name_1582`, `display_name`, `aliases` | 当時名、地図表示名、現代名・別名・読み |
| `roles`, `site_group_id` | 城／集落／港の役割。同一地域内の関連地点 |
| `province_id`, `region_id` | 旧国・作業地域。境界不明なら保留できる |
| `temporal_status`, `temporal_note` | `attested`／`inferred`／`unresolved`／`out_of_period` と判断理由 |
| `name_status`, `name_note` | 名称の確認状態と採用理由 |
| `validity_evidence` | 成立・利用・移転・廃絶の根拠と年代幅。不明な開始・終了は空欄 |
| `lonlat`, `location_status`, `location_note` | 原位置、位置の状態、選定・座標変換の方法 |
| `uncertainty_m`, `display_anchor` | 根拠のある誤差値または空欄。表示上の移動は別管理 |
| `importance`, `selection_reason` | 表示優先度と、主要拠点として選んだ根拠 |
| `adoption_status`, `adoption_reason` | `accepted`／`deferred`／`excluded` と理由。史料評価と独立 |
| `source_refs`, `claims` | 名称・年代・位置・機能それぞれに対応する出典IDと該当箇所 |
| `connection_anchors` | 陸路・水路の接続位置と確認状態。未調査は空配列 |
| `review_notes` | 異説、未確認事項、確認担当・更新日 |

採用済みでも年代・位置が推定の場合がある。単一の「確度」だけで全項目をまとめない。元資料の確認が増えたら該当項目を更新し、採用状態の変更だけで史料評価を上げない。

## 8. 既存176地点と道路を照合する

本書作成時点の道路台帳は81回廊・176地点を含み、城や集落の厳密な台帳ではない。最初に `data/derived/roads/roads_1582.json` と生成元を読み、既存の名前・ID・座標・出典を抽出する。

各地点を「同じ史跡・集落と確認」「同名だが別地点」「概略通過点」「照合保留」に分類する。名前や距離だけで自動統合しない。佐土原・鹿児島などの既存点も、道路の代表点であることを踏まえて再確認する。

対応表には道路の `node_id` と拠点の `site_id`、対応の種類・根拠・座標差を記録する。1つの概略点が城と港など複数の実地点に対応する場合も扱えるようにする。

この工程では、照合結果だけで既存道路の座標を一括移動しない。次の道路工程で接続先を選び、必要な区間だけ調整して水系・地形検査を再実行する。番号付きの9通過点は維持し、拠点名と重複するラベルは表示側で統合する。

## 9. 地図上の表示仕様

- 城・集落・港を道路とは独立したレイヤーに置き、全体と種類別の表示を切り替えられるようにする。
- 城は城郭記号、集落は丸、港は錨など、色だけでなく形で区別する。
- 名称は画面上で一定の読みやすいサイズを保つ。広域では主要拠点、拡大時には地域中心・補助拠点を表示する。
- 選択中の地点はラベルを優先し、画面端・操作パネル・他ラベルと重なる場合は位置を調整する。名称を消すだけにせず、一覧検索と地点への移動を用意する。
- 地点詳細に種類、当時名と別名、年代判断、位置の状態、出典、採用理由を表示する。
- 推定地点には輪郭や小さな印と凡例を付ける。番号は選択中の接続順などに使い、固定の拠点IDとは分ける。
- 平面・立体で同じ地理位置を使い、既存の標高投影に追従させる。立体表示だけ別座標を保存しない。
- 城の天守模型や集落の面積は、点の配置から推測して作らない。最初は位置を確認できる記号と名前を実装する。

通常表示は採用済みで位置を置ける地点を対象とする。保留地点は調査用表示で確認できるようにし、位置未特定の地点は一覧に残す。調査用表示を消したことを、地点の削除と混同しない。

## 10. 地域ごとの実作業

1. **既存データ確認**：基礎地図・水系・道路台帳の版とハッシュを記録し、対応する既存通過点を抽出する。
2. **候補収集**：城・集落・港を種類ごとに収集し、重複、別名、未調査地域を記録する。
3. **年代・機能確認**：対象時点の状態と主要拠点としての役割を調べ、主張ごとの出典を付ける。
4. **位置確認**：原位置と位置の状態を決め、旧国・水系・基礎陸地との不一致を調べる。
5. **選定**：根拠を満たす地点を採用し、不十分なものは保留、時代違い等は理由付きで除外する。
6. **配置**：派生データを生成し、名前付きの記号と詳細表示、種類別切替を実装する。
7. **表示確認**：地域全体と密集箇所を平面・立体で確認し、ラベルと原位置の対応を修正する。
8. **地域記録**：採用・保留・除外の件数、資料の不足、未配置地点、画像、既存道路との対応表を保存する。
9. **次地域へ展開**：同じ基準を使って進め、前地域で必要になった仕様修正を共有する。

通常の調査・配置・修正のたびに承認待ちを設けない。新しい拠点の創作、対象年代・地理範囲の変更など、既存方針から外れる判断が必要な場合だけ、該当地点と選択肢を示して相談する。本書の作成だけで配置や道路生成を開始したことにはしない。

## 11. 検証と完了条件

### データ検査

- ID重複がなく、出典・拠点群・道路対応の参照先が存在する。
- 採用地点には種類、表示名、選定理由、年代・位置それぞれの確認記録がある。
- 活動中の拠点に対象時点で廃絶した地点や後代成立の地点が混入していない。
- 座標の経緯度順・範囲・測地系・ゲーム座標変換が正しい。未特定を `[0,0]` で代用しない。
- 陸地外、水面上、旧国境付近、近接同名の地点を要確認として抽出し、理由を残す。
- 既存の基礎ポリゴン、水系表示設定、道路の採用状態が意図せず変わっていない。
- 編集正本からの再生成で同じ結果になり、派生JSONだけを手修正していない。

### 画面検査

- 平面・立体、既存5段階LODで記号と名前を確認する。
- 密集した城下・港、山城、海岸や河川付近、画面端を含む実画面を保存する。
- 選択した地点名は読め、記号を指している。検索と地点移動で非表示の補助拠点にも到達できる。
- 拠点レイヤーの表示切替が、主要河川・湖・国境・道路を誤って切り替えない。
- 配布版を作る段階では、新しい派生データ・描画スクリプトが含まれ、起動・表示できることを確認する。

**地域の初版完了**は、地域の主要候補を城・集落・港の各種別で一巡し、全候補の採用・保留・除外を理由付きで整理し、採用地点を表示・検証できた状態とする。保留や未調査が残る場合は一覧に明記し、「全拠点を復元済み」とは記載しない。

## 12. 道路工程への引継ぎ

配置後は、拠点IDと実際の接続位置を使って既存回廊への連絡を検討する。山城の主郭から直接幹線を引かず、登城口や麓の集落を接続点として確認する。港の記号も、陸路終点や航路終点とは別に判断する。

史料で確認できる道とゲーム用の推定連絡路は、どちらも採用可能な道路として管理する一方、区間ごとに根拠を分けて保存する。推定連絡路には、結ぶ拠点、補完理由、主要通過点、峠・渡河の確認状態を付ける。

接続案は、ユーザーが確認できる番号付き通過点と地名で描画する。直線距離が近いだけで接続せず、山越え・水系・既存幹線との関係を検討する。地図上で線が交差していても、共有接続点を登録するまで分岐・合流として扱わない。

この引継ぎ仕様により、拠点の位置と根拠を保ちながら、地域の道を増やしていける。
