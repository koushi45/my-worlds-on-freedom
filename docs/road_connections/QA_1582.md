# 道路接続初版の検証記録

対象は1582年・本能寺の変の直前、配置済み250拠点。新規281路線は全てゲーム用の推定連絡路。史料で新たに1582年の利用を確認した路線は0本。

## 集計と読み方

|項目|件数|
|---|---:|
|対象拠点|250|
|推定接続域まで接続済み|246|
|接続保留・未着手|0|
|理由付き陸路対象外|4|
|新規路線|281|
|共有IDで分割した描画・検査区間|1,831|
|うち推定渡河区間|625|
|陸路網の成分|3（本州198拠点、九州33拠点、四国15拠点）|

平戸・宮島・上関・勝山館は対象集合内の別拠点へ陸路だけでは到達できないため航路の別工程とする。625は水系IDの数や異なる川の数ではなく、両側の接続点を持つ渡河区間数。同じ川を複数箇所で渡る場合を含む。

旧81回廊は比較用の別レイヤーとして維持する。新規網だけで到達を検査し、旧回廊との単なる画面上の交差から合流・橋を推定しない。新旧交差・176地点との対応は `data/derived/road_connections/topology_review.json` に記録する。

## 自動検査

- `test_road_connections.py`：250件の状態と入力ハッシュ、共有端点ID、各拠点の到達、選択路線自身の連続性、描画線と区間の一致、海・湖・全水系交差、渡河参照、史料確度の独立性を検査。
- `audit_road_connection_topology.py`：新規網の見かけ上の交差が共有ノードへ分割されているかを独立検査。旧回廊の交差は別一覧にする。
- 既存の拠点・歴史回廊のPythonテスト12件で、拠点採否・地方件数・水系・既存81回廊の状態を検査。
- Godotの `test_road_connections.gd`：読み込み、名称検索、路線選択、通過点表示、拠点の接続状態、独立レイヤー切替、5段階LODを検査。

実行結果は配布フォルダーの `qa/road_connections_python.log`、`qa/road_connections_topology.log`、`qa/road_connections_runtime.log` に保存する。配布版の実測結果は `build_report.json` に記録する。

今回の結果：新規4件＋既存12件のPython検査が合格。新規網の未解決交差0、旧回廊との交差167件を比較用として別記録。旧道路176地点には複数の対応関係を含む182行がある。Godotの実描画・配布PCKの接続テストが合格し、最新版EXEの起動は終了コード0。Windowsエクスポートにエラーなし。

## 精度の限界・次に修正できる箇所

約453mの実標高は谷の概形を比較する資料であり、細い古道・門・登城口の証明にならない。推定接続域は記号から最大1.8kmの範囲で選び、記号の正本座標は動かしていない。城の主郭までの登城道は残件として表示する。

海・湖を横断しないことと、渡河を登録することを検査している。現代の河道・ダム湖・海岸線を使っているため、1582年の地形の復元とは異なる。中心線のみの川では実際の川幅と両岸位置は未確認。渡河の方法、正確な峠名、道路幅、所要時間は確定していない。

比較案は距離・実標高の上昇下降・勾配・渡河・共用区間を記録する。曲線による平滑化は行わず、検査した折れ線をそのまま使用する。既存回廊も新規区間も `routable=false` を維持し、ゲーム内移動・季節や兵種の制約は別工程。

再生成は `python tools/build_road_connections.py`、続いて `python tools/audit_road_connection_topology.py`。正本と生成物の区別は [作業手順書](../ROAD_CONNECTIONS_1582_WORK_INSTRUCTIONS.md) に反映した。
