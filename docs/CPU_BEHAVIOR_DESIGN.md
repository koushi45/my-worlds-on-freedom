# CPU大名家の行動設計

作成日：2026年10月3日

CPUが担当する他家の外交・軍事・内政・人事・研究の判断を定める設計資料。CPUは原則としてプレイヤーができるゲーム内の行動をすべて実行でき、同じ資源、費用、前提条件、移動・戦闘ルールに従う。

2026年10月3日にCPUの意思決定、他家の出陣・進軍、同盟参戦を実装した。本資料は判断方針を定める設計資料とし、実装内容と確認結果は [CPU行動の実装と確認](CPU_BEHAVIOR_IMPLEMENTATION.md) に記録する。以下の数値は初期調整値とし、指定された3つの必須行動は数値調整後も維持する。

## 必須行動

1. 戦争を仕掛けられた家は同盟相手に参戦を要請し、自軍と同盟軍を実際に動かして攻撃側に対抗する。プレイヤーからの宣戦にも、CPUからの宣戦にも同じ対応を行う。
2. 自分より弱い家に積極的に戦争を仕掛ける。到達可能で、補給と防衛を維持できる弱い相手がいれば、継続的に侵攻を検討して実行する。
3. 弱い家は自分より強い家との同盟を積極的に目指す。友好度が足りなければ使節・贈物で関係を改善し、条件を満たしたら同盟を提案する。

## 行動範囲と共通ルール

ここでいう「国」は意思決定主体である大名家・勢力を指す。令制国単位では判断しない。プレイヤーの家を除く、領地を持ち活動可能な家をCPUの対象とし、独立して誕生した家も対象に含める。

| 分野 | CPUが使う行動 | 判断方針 |
| --- | --- | --- |
| 外交 | 使節派遣・帰還、贈物、同盟提案・破棄、侮辱、宣戦、停戦、参戦要請・応答 | 生存、抑止、侵攻の準備を優先する。侮辱や同盟破棄は戦略上の理由がある場合に限る |
| 軍事 | 武将配置、大将・副将選定、出陣、装備選択、経路指定、停止、方向変更、帰郡 | 防衛、援軍、侵攻、撤退の目的に応じて命令する |
| 内政 | 開発担当の選定、施設建築・中止・撤去、基盤整備、荒廃修復 | 食料不足と財政悪化を解消し、戦時は防衛と補給、平時は収入を優先する |
| 人事 | 役職、俸禄、郡・国の統治担当、所属武将の配置 | 能力と忠誠を見て配置し、出陣武将と内政担当の取り合いを調整する |
| 研究 | 前提を満たす技術の取得 | 食料、治安、忠誠、収入、兵力のうち現在の不足を改善する技術を優先する |

保存・読込、表示設定、開発者モードなどの操作は意思決定対象に含めない。登用等はプレイヤー向け機能が利用可能になった時点でCPUにも同じ条件で開放する。参戦要請・応答は新設する共通機能とし、プレイヤーにも利用可能にする。

CPU専用の無料出陣、兵力生成、資源補充、瞬間移動は行わない。停戦期間、外交行動の待機日数、友好度、領有権、武将の所属・出陣中の制約を共通の行動処理で検証する。閲覧できる情報の範囲もプレイヤーに合わせる。

## 判断の周期と優先順位

宣戦、敵の侵入、同盟参戦、領地喪失、部隊の壊滅、補給不足はイベントとして受け取り、次のゲーム日までに対応する。日々の判断では防衛と部隊命令を更新し、7日ごとに侵攻候補と同盟候補を見直す。月初には内政・人事・研究・予算を見直す。

判断の優先順位は、領地の防衛、同盟国への援軍、補給不足部隊の帰郡、必要な同盟の確保、弱い相手への侵攻、内政投資とする。防衛と侵攻が競合した場合は防衛に兵力を割り当て、外交と内政は残る資源で並行して進める。

各家は当面の目的、対象家・対象郡、担当部隊、実行期限を持つ。毎日目的を捨てて命令し直すことを避け、敵侵入や補給不足など状況が変わった場合に再計画する。

## 強弱の判断

領地数だけで強弱を決めない。戦力は、現存する野戦部隊と、武将・兵糧が揃って実際に出陣できる予備兵力から見積もる。同じ兵を野戦部隊と予備兵力に重複計上しない。

初期案では、各部隊の兵数に指揮能力・装備の係数を掛け、対象戦線へ到達できない部隊は除外する。係数は実際の戦闘計算を基準に調整する。城や奉行所の守備力は野戦兵力に加算せず、攻略に必要な損害と日数として別に評価する。

全国の潜在戦力と、特定の戦争に投入できる戦力を分ける。後者では他戦線の拘束、移動時間、兵糧、残す守備兵を差し引く。同盟国は参戦条件と到達可能性を確認し、援軍として使える兵力だけを算入する。

- **弱い相手の初期基準**：相手単独の投入可能戦力が自家の80%以下。
- **侵攻実行の初期基準**：相手の防衛同盟軍を含めた戦力に対して、攻撃側が1.25倍以上の投入可能戦力を確保できる。
- **保護が必要な家の初期基準**：到達可能な近隣勢力の中に、自家の1.25倍以上の潜在戦力を持つ家がある。

戦力がともにゼロの場合は侵攻しない。相手の野戦兵力がゼロでも、自家に城・奉行所を攻略する兵と補給がなければ宣戦しない。強弱は固定属性にせず、戦争、損失、開発、同盟に応じて再評価する。

## 宣戦されたときの防衛と同盟参戦

宣戦または中立相手への攻撃で戦争が始まった時点で、防衛側は防衛目的を設定する。現在の `on_hostile_attack` 相当の経路から始まった戦争も同じイベントに集約する。

1. 攻撃側、侵入経路、守る郡、現存部隊と出陣可能兵を確認する。
2. 戦争開始時点の直接の同盟国すべてに防衛参戦を要請する。
3. 条約上参戦可能なCPU同盟国は防衛要請を受諾し、攻撃側との敵対関係を設定する。自身が弱いことだけを理由に参戦を断らない。
4. 防衛側は侵入地点や失う危険が高い郡へ部隊を集め、同盟国は援軍の目的地を選び、出陣と移動命令を実行する。
5. 守備に必要な戦力を確保した後、敵部隊の撃破、占領された郡の奪回、敵領への反撃へ進む。

同盟国が攻撃側とも同盟している場合は、防衛側への義務を優先し、攻撃側との同盟破棄を共通ルールで処理する。攻撃側との停戦が残る場合は参戦待機として記録し、停戦終了後に戦争が続いていれば参戦する。この扱いと同盟破棄の威信への影響はプレイヤーにも共通とする。

同盟の同盟へ無制限に要請を連鎖させない。同じ戦争への重複参戦を防ぎ、要請対象は当初の防衛側の直接の同盟国に限定する。プレイヤーが同盟国の場合は参戦要請を通知し、プレイヤー自身が応答する。

兵や武将・兵糧が不足する家は参戦しても直ちに出陣できない。その場合は準備中の理由を記録し、毎日再確認して条件を満たしたら援軍を出す。到達不能の場合も理由を記録し、領地の防衛や別の到達可能な敵郡への攻撃を検討する。外交状態の変更だけで援軍処理を完了扱いにしない。

## 弱い家への積極的な侵攻

7日ごとの評価で、隣接する家と現在の移動ルールで領地まで到達できる家から侵攻候補を選ぶ。中立で停戦中ではなく、自家より弱い家を対象とする。同盟国は対象から除外する。

候補ごとに戦力差、相手の同盟、到達時間、攻略日数、補給、得られる郡の価値、別方向から攻められる危険を評価する。有利な候補があれば侵攻目的を設定し、武将を配置し、出陣兵力と経路を準備する。条件を満たしているのに毎回ランダムで行動を見送る設計にはしない。

初期案では、自領防衛用に出陣可能兵の30%を残し、往復移動と攻略の見込み日数に余裕15日を加えた兵糧を確認する。実際の腰兵糧上限を超える計画は短い目標に分割する。準備が整った次の評価日に宣戦し、出陣・進軍へ移る。

一度に開始する自主的な侵攻は原則1件とする。宣戦後も敵が兵を増やしたり援軍を得たりした場合は再評価し、目標縮小・撤退・停戦交渉へ切り替える。新たに宣戦された場合の防衛はこの件数制限に含めない。

## 弱い家の同盟形成

強い近隣家に脅かされている家は、使節と贈物の予算を優先確保して同盟を目指す。候補は自家より強く、援軍として到達でき、脅威に対抗できる家とする。自家を現在攻撃している家は保護者候補にしない。

候補の評価には強さ、距離、友好度、共通の脅威、既存の戦争、援軍に回せる余力を使う。最有力の家に使節を派遣し、贈物の費用が払え、必要な俸禄・防衛予算が残る場合は贈物も使う。現行の同盟条件である相手の友好度40以上等を満たしたら同盟を提案する。

初期案では防衛同盟を2家まで目指す。断られたり条件が整わなかったりしても目的を取り下げず、外交の待機期間後に再試行するか次候補へ切り替える。自家が強くなった後も、戦力が少し変わっただけで同盟を破棄しない。

現行の同盟成立は友好度等の条件を満たすと即時成立する処理であり、受諾側の戦略判断はない。最初のCPU対応でもこの共通条件を使用する。将来、提案の受諾・拒否を導入する場合は、プレイヤーからの提案にも同じ評価を適用する。

## 部隊の移動と戦闘判断

防衛部隊は近い敵部隊と危険な郡を優先し、侵攻部隊は攻略可能な奉行所・城を目標にする。同盟援軍は防衛側の不足戦力を補う目標を選ぶ。複数部隊で同じ敵を狙う場合は集合地点を決め、到着時刻を合わせて孤立を避ける。

部隊命令は六角形の隣接経路を使用し、地形・道路による所要日数、通行不可、味方・敵の位置を確認する。未実装の航路や輸送を前提に海を越える計画は作らない。敵に接近したら射撃方向と近接戦闘の戦力差を見て移動・停止・方向を選び、現在の戦闘処理を使う。

毎日、残兵数と帰郡所要日数を確認する。初期案では、腰兵糧が帰郡所要日数に余裕10日を加えた値以下、または兵数が出陣時の40%未満になったら帰郡を優先する。帰郡完了後の再出陣も兵・武将・資源の共通条件で判断する。

## 内政と人事の判断

月初に収入、俸禄、兵糧、開発、忠誠を評価し、翌月の俸禄と予定した出陣費用を確保した残額で投資する。戦時でも収入と兵糧の供給を維持し、すべての武将と資源を前線に投入しない。

政治能力の高い武将を開発と統治に、指揮・武勇等に優れる武将を出陣候補に配置する。忠誠不足で出奔・独立の危険がある重要武将には、財政の許す範囲で俸禄や役職を見直す。施設は効果と費用を比較し、防衛線の整備、荒廃修復、農業・商業への投資を選ぶ。中止・撤去は不足予算や建築枠を解決する必要がある場合に行う。

研究は取得可能な次の技術のうち、現在の不足を改善するものを選ぶ。未実装の研究分岐や効果を選択肢に追加しない。

## 実装時の接続先

以下は確認した現行コードと、追加実装が必要な点の対応である。

| 現行コード | 現状と必要な変更 |
| --- | --- |
| `scripts/main/main_map.gd` | 日付更新を各機能へ接続している。CPU判断の更新を追加し、既存の経済・補充等の更新後の状態で判断する |
| `scripts/game/diplomacy.gd` | 外交の条件検証・実行・月初の使節効果がある。戦争開始イベント、参戦要請・応答、戦争参加者管理を追加する |
| `scripts/game/army_campaign.gd` | 出陣・移動命令等がプレイヤーの家に限定されている。実行主体の家を受け取る共通処理にし、UIの自家限定チェックは維持する |
| `scripts/game/district_economy.gd` | 全郡の収入・開発更新と担当割当がある。CPUの担当選定を追加し、所属・所有権等の必要な検証を共通化する |
| `scripts/game/district_actions.gd` | 整備・修復・月初の兵補充がある。CPUから既存の費用と所有権検証を使う |
| `scripts/game/district_buildings.gd` | 建築・中止・撤去・完成更新がある。CPUが投資先を選んで共通処理を呼ぶ |
| `scripts/game/retainer_management.gd` | 人事・配置・俸禄・忠誠危機・技術力の更新がある。CPUの人事判断を追加する |
| `scripts/game/technology_tree.gd` | 研究の前提と技術力消費がある。CPUも同じ処理を使う |
| `scripts/game/game_session.gd` | 保存・読込にCPUの目的、部隊任務、戦争参加者、参戦待機、次回評価日等を追加する |

部隊命令の共通化では、CPU出陣によってプレイヤーの選択部隊やUI表示が切り替わらないようにする。行動直前に条件を再検証し、費用の二重払いと同じ武将の重複出陣を防ぐ。

判断ログには、選んだ行動、対象、戦力の比較値、実行した命令、見送り理由を残す。保存・読込で戦争や援軍を重複開始しない。開発中の旧セーブ形式への移行処理は追加せず、変更後の形式で再開できることを確認する。

## 実装後の確認条件

| 場面 | 確認する結果 |
| --- | --- |
| プレイヤーが同盟国を持つCPU家に宣戦 | 防衛側が要請し、参戦可能なCPU同盟国が参戦する。兵・武将・兵糧が揃う家は実際に出陣・進軍する |
| 中立相手の領地を攻撃して戦争開始 | 通常の宣戦と同じ防衛・援軍処理が始まる |
| CPUの近隣に弱い家があり侵攻条件を満たす | 評価、準備、宣戦、出陣、移動、攻略まで進む |
| 弱い相手に強い防衛同盟国がいる | 同盟軍込みで再評価し、無謀な侵攻を避けて準備または別候補を選ぶ |
| 弱いCPU家の近くに強い家がいる | 保護者候補へ使節・必要に応じた贈物を使い、条件成立後に同盟を提案する |
| 防衛側と攻撃側の双方に同盟している家 | 防衛義務を優先し、矛盾した同盟・敵対状態にならない |
| 兵糧不足、武将不足、到達不能 | 無料出陣や瞬間移動をせず、準備・帰郡・別目標の理由を記録する |
| 内政・人事・研究 | 共通条件と費用を守って実行し、防衛・俸禄予算を考慮する |
| 多数の家が同時に判断 | 二重出陣・重複参戦がなく、通常のゲーム速度を維持する |
| 戦争・援軍・進軍途中で保存して読込 | 目的と参加者を維持して再開し、費用や参戦イベントを重複処理しない |

機能実装の完了時には、必須3行動のシナリオ確認、現行形式での保存・読込確認、Windowsリリース版の書き出しと起動確認を行う。
