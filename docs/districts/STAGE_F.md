# 工程F：ゲーム内の郡表示・選択

2026-09-12。現在のGodotプロジェクトに、独立した郡レイヤー、表示切替、選択モード、検索・詳細欄を追加した。工程Dの748区画（候補673・未確定75）を対象にする。史料上の採用状態は保留を維持する。

## 操作

画面上部、推定連絡路の下にある「郡境」で表示を切り替える。「国を選択／郡を選択」でクリックの対象を変更する。郡モードでは拠点記号の場所でも地表の区画を調べる。国モードでは既存の拠点・国の選択動作を維持する。

「郡一覧・検索」は国名・郡名・IDで検索できる。地図で省略された名前や未確定領域も一覧から選べる。選択後、「選択した郡を地図で見る」で代表点へ移動する。移動時の上限は既存の400%。

境界付近をクリックすると複数候補を一覧に表示し、自動で片側を選ばない。候補が一つの場合は詳細を開く。郡境表示だけを消しても、選択モードは独立して保持する。

## 表示と出典

- 全国表示では郡の細線・郡名を描画しない。ズーム65%以上で内部境界、100%以上で郡名を表示する。
- 郡境は画面基準0.9pxの破線。国境・海岸は既存レイヤーが描き、工程Dの `parent_outer` は郡の通常線にも選択線にも追加しない。
- 郡名は14px。画面上の文字サイズを保ち、郡名同士、拠点の周囲、操作パネルに重なる場合は省略する。省略した名前は一覧検索で選択可能。
- 代表点は各区画の大きな連続部分の内点。全748件で、その郡の面内・穴の外・基盤陸地上にあることを検証した。塗りの穴とクリック判定の穴も保持。
- 郡の詳細には国名、郡名、1582年という対象年、後世の資料年代、採否、確度、位置包含・近傍による拠点候補、出典、残件を表示する。
- 全候補は保留。拠点欄も歴史的所属の確定を意味せず、工程Eの曖昧・未確定状態を表示する。史料所属と面判定が食い違う拠点は、その旨を付記する。

資料の出典とCC BY-NC 4.0の条件は郡詳細と既存の「出典・ライセンス」欄に追加した。背景タイルや国の元データには書き込んでいない。

## 描画・選択の構成

|ファイル|役割|
|---|---|
|`scripts/map/district_layer.gd`|空間索引、表示範囲のロード、内部破線、ラベル、地表に沿う選択塗り、穴と境界許容距離を考慮する選択|
|`scripts/map/district_panel.gd`|郡境切替、選択モード、検索、複数候補、詳細、移動|
|`scripts/main/main_map.gd`|独立レイヤーの追加と既存カメラ・表示・逆変換との接続|
|`tools/build_district_stage_f.py`|工程D・Eから表示用キャッシュを生成|

国別の詳細形状と区画メタデータを分け、128ワールド単位の格子索引で表示・クリック範囲を検索する。内部線にも索引を持つ。全国表示では詳細形状をロードせず、拡大した表示範囲に関係する国だけを読み込む。画面外の国とその投影線キャッシュは解放する。選択塗りのメッシュは選択した一つの区画だけを読み込む。

線は既存 `elevation.project_line`、クリックは既存 `_screen_to_world` → `elevation.unproject` を使用する。境界の許容距離は投影した線に対して画面上6pxで判定する。立体時の候補検索範囲は起伏分も含めて広く取り、最後の判定を画面距離に限定する。

塗りは既存地表の16×16格子と同じ対角線で区画を分割し、その内部だけで三角形化した。既存 `elevation.project` で各頂点を投影するので、平面・立体とも同じ地表の区画となる。元の面・線の座標はJSONに保持。選択塗りの頂点だけをfloat32バイナリへ格納しており、編集正本を丸めてはいない。

表示キャッシュは約117MiB、内部線5,344本、地表に沿う三角形1,550,029枚。これを全て同時描画する構成ではない。表示キャッシュは `data/work/districts/stage_f/` に保存し、元の工程D・Eを変更しない。

## 検証

[データ検証記録](../../data/work/districts/stage_f/qa.json)／[平面400%](../../builds/qa/district_400_flat.png)／[立体400%](../../builds/qa/district_400_oblique.png)／[詳細欄](../../builds/qa/district_details.png)／[全国表示](../../builds/qa/district_national.png)

データ検証では全748代表点、元の共有線との一致、国境線の除外、三角形の地表格子・対角線との一致、穴を含む塗り面積、入力68ファイルのハッシュを確認した。基盤陸地上のラベル位置も確認した。

Godotの実行テストでは、全国で詳細形状をロードしないこと、移動後の画面外データ解放、全代表点の包含、穴の除外、表示のオフ／オン、選択モード、複数候補の非自動選択、検索と詳細を確認。平面・立体とも境界上と境界から画面上3pxのクリックで両側候補を返すことを検証した。既存の400%ズーム・拠点移動・路線移動の回帰テストも通過した。

実GPU描画の画像を保存し、国境と郡境の区別、地形に沿った塗り、文字の省略、詳細欄を目視確認した。

```powershell
python -X utf8 tools/build_district_stage_f.py
python -X utf8 tools/verify_district_stage_f.py
godot_console --headless --path . --script res://tests/base_map/godot/test_districts.gd -- --district-review
godot_console --headless --path . --script res://tests/base_map/godot/test_detail_zoom.gd
```

工程G以降、通常起動は採用済みデータだけを読み込む。以下は工程F時点の記録であり、保留候補の比較にはエディター版Godotの起動引数 `-- --district-review` を指定する。[工程Gの現行仕様](STAGE_G.md)を参照。既存のWindows配布版exeは更新していない。今回の研究用キャッシュは従来の `data/work/*` のエクスポート除外を維持しているため、既存の配布プリセットでは郡データを同梱しない。データがない場合、郡パネルは比較データがない旨を表示し、既存の地図機能は動作する。

史料の追加調査、採用判断、配布用データの選定は後続の作業として残る。今回の表示機能の追加によって、未確認の郡境・拠点所属が確定した扱いにはならない。
