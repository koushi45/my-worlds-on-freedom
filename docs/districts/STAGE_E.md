# 工程E：拠点・推定連絡路との対応

作成日：2026-09-12。登録経緯度と既存の8192×8192座標変換を使用。

**254拠点の座標照合と285路線の通過区画・境界通過点の派生を実施した。史料上の所属の全面照合は未完了で、所属史料が未確認の252拠点を残件として明示する。** 計算上の包含候補、登録位置の確かさ、史料上の所属は別々に保存した。

[拠点別の照合表](STAGE_E_SITES.md)／[285路線の通過順](STAGE_E_ROADS.md)／[検証結果](../../data/editorial/districts/stage_e/qa.json)／[個別判断](../../data/editorial/districts/stage_e/individual_reviews.json)

## 入力範囲

道路側の `site_connections` にある254件のIDを依頼対象として固定した。拠点ファイル自体には268件があり、残る14件は別枠の参考レコードとして照合した。これらには調査候補・対象外の後世城などが含まれ、本工程で14拠点を新規採用したわけではない。

入力は拠点登録、推定連絡路、工程Dの66閉区画、座標変換、今回の所属証拠台帳。参照した原図を含め71ファイルのハッシュを[入力台帳](../../data/editorial/districts/stage_e/input_manifest.json)に保存した。

## 拠点の座標判定

`lonlat` を基準地図の変換で投影し、工程Dの全親領域の面に対して包含を計算した。登録済み `point` との差は全件0。表示記号用の `display_point`、`display_anchor`、道路の `connection_anchors` は所属判定に使用していない。国名から候補を限定して、別の国の面に入る事実を隠す処理もしていない。

|依頼対象254件の状態|件数|
|---|---:|
|`ambiguous`|221|
|`unresolved`|33|
|確定した歴史的郡所属|0|

今回の全登録位置は `area_estimate`、位置誤差幅は未定量だった。候補の内部に入る場合も、地域代表点から城域の所属を確定することは避け、曖昧として包含候補を残した。

判定規則：

- 境界上、複数区画に包含される場合、境界付近：`ambiguous`。
- 工程Dの未確定区画内、親領域の外側、位置未確定：`unresolved`。
- 最近傍の区画への割当は行わない。付近の候補は検討用リストに留める。
- 基本の境界検査幅は500m。登録された誤差幅がこれより大きければそちらを用いる。500mは調査用の検査範囲であり、史料や登録座標の精度を保証する幅ではない。
- 親領域外は簡略海岸、親領域未収録、位置誤りなどをまだ区別できない。海上と断定せず、その理由の確認を残す。

[全件JSON](../../data/work/districts/stage_e/site_assignments.json)には登録経緯度、投影点、包含区画、近傍の区画、境界までの距離、位置根拠、状態と理由、既存資料の参照先を保存。区画IDは親領域IDとの組で識別する。

## 史料上の所属との照合

既存の構造化された拠点台帳は名称・年代・位置・機能の根拠が中心で、郡所属の確定欄はない。その出典一覧を郡所属の証拠と読み替えず、各拠点に確認先と未確認状態を記録した。現代住所にある「郡」も1582年の所属には自動採用しない。252件について、新たな所属史料の確認が必要。

今回の個別照合は[所属証拠台帳](../../data/editorial/districts/stage_e/affiliation_evidence.json)に参照箇所・年代・判断の限界を記録した。

|拠点|所属資料・調査候補|登録座標の面判定|判断|
|---|---|---|---|
|岸和田城|元禄国絵図の南郡の色分け・城記号|南郡|後世の比較では一致。1582年への継続は未確認|
|石山本願寺|尼崎地域史事典が説明する東成郡生玉荘内|西成郡|文献所属と面判定が不一致。旧寺域の比定・時代差を個別検討|
|筒井城|筒井郷について添下郡とする括弧付きの比定が調査候補|平群郡|城そのものへの直接証拠ではないため、確定した所属矛盾とは扱わない|

石山本願寺の文献記述は、1496〜1580年の寺院を説明する後世の解説。登録座標は後世の大坂城跡を使う地域代表点で、1582年の旧寺域の精密位置ではない。文献に合わせて点を動かすことも、面に合わせて文献所属を書き換えることもしなかった。[尼崎地域史事典・石山本願寺](https://www.archives.city.amagasaki.hyogo.jp/apedia/index.php?key=%E7%9F%B3%E5%B1%B1%E6%9C%AC%E9%A1%98%E5%AF%BA%EF%BC%88%E6%B5%84%E5%9C%9F%E7%9C%9F%E5%AE%97%EF%BC%89)

筒井郷の記録は文明11年（1479）、引用先は『大乗院寺社雑事記』・『橿原市史』2 p.410。公開表の郡欄は括弧付きであり、原典の直接閲覧と城域との対応確認は残件。[ムラの戸籍簿・大和国](https://drfh.jp/mura/index.php?title=%E5%A4%A7%E5%92%8C%E5%9B%BD)

岸和田は工程Cに保存した元禄図の原画像の城記号と南郡の黄色を目視照合した。精度不足で保留した補正画像の面判定を、原図の独立した証拠として循環利用していない。

## 道路の通過順と境界通過点

285路線の `routes[*].points` を読み、路線ごとの別JSONへ派生した。元の点列・出入口・道路網・通行可能属性には書き込んでいない。

各元線分で境界との交点を計算し、路線始点からの累積距離順に区間化する。全路線を一本の線として最初の交点へ逆投影すると、折返しや同じ場所の再訪で順序を失うため、元線分番号と線分内比率を保持した。

|出力|内容|
|---|---|
|`intervals`|通過区画の順序、始終点の累積距離・元線分番号・比率、区画候補／未確定／境界沿い等の状態|
|`boundary_events`|境界通過点、累積距離、元線分位置、境界ID、前後の区画|
|`geometry_sha256`|元点列のハッシュ。派生先に修正した道を作らない|
|`zero_length_input_segments`|元に同一点の連続があれば、その位置を記録|

実データの境界通過イベントは1,368点。区間は候補内1,210、未確定または表示区画外443、数値接点9。隣接する国の外周との演算差などで生じた10⁻¹³〜10⁻¹²ワールド単位程度の極小区間は `numeric_contact_interval` として保存し、実際に別の郡を通過したとは判断しない。イベントの同一点整理の許容値は1e-8ワールド単位で、歴史的な境界の移動には用いない。

接するだけの点、境界に沿う線、端点での接触も別の種類として処理可能。実データでは極小区間を分けるとイベントはすべて通常の通過となった。境界沿い・接触・折返しの挙動は合成データで検証した。

区画外の通過は既存の道に対する診断であり、新しい海峡横断線を追加する指示ではない。工程Dの隣接台帳から道路を生成する処理はない。道路側で陸路対象外の平戸・勝山館・宮島・上関の4件にも、新たな陸路を作っていない。

郡境通過による関所、移動不可、通行税、敵領判定を追加していない。これまでの道路の `routable` を変更する処理もない。

## 検証と再生成

実データで登録座標の包含、全路線の区間連続性・総延長、区間中点の所属、通過点が元線と境界上にあること、元入力のハッシュを検証した。通過点の元路線からの最大数値ずれは約4.5×10⁻¹³ワールド単位。合成データでは折返し再通過、境界沿い、ゼロ長線分、接するだけの点、区画外、記号・出入口を動かしても城の判定が変わらないこと、史料との不一致保持を確認した。

```powershell
python -X utf8 tools/build_district_stage_e.py
python -X utf8 tools/report_district_stage_e.py
python -X utf8 tools/verify_district_stage_e.py
```

作業結果は `data/work/districts/stage_e/`、入力・根拠・判断台帳は `data/editorial/districts/stage_e/`。工程Dの図形と道路・拠点の元データは維持した。配布用への組み込みは行っていない。

残件は、252拠点の郡所属資料の確認、石山本願寺などの個別位置比定、概略座標の誤差幅の検討、未確定区画の採否判断。史料未確認を一致と表示せず、`adopted_historical_district_id` は全件 null とした。
