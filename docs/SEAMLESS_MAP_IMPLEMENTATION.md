# シームレス地図の実装と検証

2026-09-13。仕様元は [SEAMLESS_MAP_PROPOSAL.md](SEAMLESS_MAP_PROPOSAL.md)。マップのみのゲーム画面、400%の操作倍率、内部の地理・武将データを維持した。

## 実装

- **全国図を常駐**：平面・立体の両方を起動時に準備する。各約6MiBの管理値。白い陸地マスクだけでなく、地形色・陰影・海岸線を合成した1024px画像と粗いメッシュを使用する。最初の描画と文字準備が完了してから入力を受け付ける。
- **表示を保持して差し替え**：ズームで全タイルを破棄しない。新しいタイルを描画ノードへ登録し、フレーム境界を越えるまで重なる領域の旧タイルを保持する。全国図は常に背面へ描画する。投影切り替えも準備済みの全国図を同じ更新内で選び直す。
- **先読み**：近隣1タイル相当、移動方向と実測読み込み時間から見積もった前方、隣のLODを要求する。候補は最大24件、容量不足時は見送る。現在必要な資産を最優先、次のLODを次優先にする。入力はフレームごとにまとめ、静止時には新たな可視範囲走査やI/Oを行わない。
- **LODの往復抑制**：切り替え基準に拡大側1.08倍・縮小側0.92倍の幅を設ける。操作倍率と表示精細度を分離する。
- **容量予約**：テクスチャの形式・mipmap、メッシュ配列、データ、共有資産の参照を管理する。読み込み開始前に作業領域を予約し、キャッシュから消しても表示中の資産が残る問題を、表示中・常駐資産の保護と参照計上で扱う。最近2.5秒の資産は古い資産より優先して保持するが、表示に必要な容量の確保を優先する。
- **郡境の事前生成**：国別データに空間索引を持たせ、1,769個の空間・投影別バッチへ分割した。1バッチは最大1,024線分。破線はGPUで描き、倍率変更時にCPUで破線分割をしない。頂点色の量子化を考慮し、累積距離を24bit固定小数点で格納する。
- **CPUの並列化**：国境・道路・水系の地表投影、元データからの郡読み込み・検証、郡選択を独立したワーカーへ分担する。入力と出力はジョブ専有または読み取り専用。シーンへの反映はメインスレッドで行い、操作中は未完了タスクを待たない。PC最大4件、Android最大2件、CPU作業予約は16MiB。
- **描画負荷の削減**：遠景タイルの地形格子を粗くし、河川・湖岸も再利用する線メッシュへ変更した。GPU登録は約1.5msを目安に分割する。地名の日本語フォント・縁取りを起動中に準備し、初表示の約280msの遅延を操作前へ移した。拠点ラベルの配置計算は約120ms間隔に抑える。
- **低メモリ対応**：Androidの地図関連管理予算は128MiB。CPU作業領域、保持する投影結果、道路・国境の線バッファを差し引いてストリーム側の予算を決める。OSのメモリ警告時は先読みを4件へ減らし、精細度を落として全国図を維持する。
- **ライフサイクル**：アプリの一時停止中は停止監視の誤検知を抑え、復帰時に状態を更新する。終了時に実行中タスクを回収する。古い要求の郡処理結果は画面へ反映しない。

## ログ

保存先は `%APPDATA%\Godot\app_userdata\My Worlds on Freedom\logs\`（Windows）。AndroidではGodotの `user://logs/`。

`map_diagnostics_<プロセスID>.jsonl` に保存する。同時起動した旧版とのファイル衝突を避けるため、従来の固定ファイル名から変更した。各ファイルは約2MiBで交代し、過去3世代を保持する。終了済みセッションは新しい3件を保持し、実行中セッションは削除しない。エンジンの標準ログは `godot.log`。

ログ生成側は上限付きキューへイベントを入れて返る。通常イベント224件・重要イベント込み256件の上限を設け、間引いた件数も保存する。JSON化・書き込み・flush・世代交代はログ専用スレッドで行い、状態共有ロック中にファイルI/Oを行わない。独立した監視スレッドも維持した。

セッション、プロセス内のスレッドID、ジョブ、要求世代、対象資産、経過時間、資産・CPU予約量、キャッシュ利用、描画処理時間、表示被覆の状態を記録する。エラー時には直前32件のイベント履歴も含める。国境・郡境等の遅い描画処理と遅いストリーム反映も個別に記録する。

`-- --map-profile` では状態記録を通常10秒間隔から1秒間隔へ変更できる。`-- --map-fps=30` または `-- --map-fps=60` でフレーム上限を指定できる。Androidの既定値は30fps。画面へ開発用UIは追加しない。

## 検証

RTX 4060、Godot 4.7.2、Compatibility、1280×720で検証した。128MiBの地図管理予算を設定し、全国〜400%の往復、3地方の移動、両投影、500msの読み込み遅延、読み込み失敗、古いCPU結果の破棄を組み合わせた。

PC測定は [qa.json](../builds/seamless/qa.json)、配布PCKでの測定は [qa_export.json](../builds/seamless/qa_export.json)。実描画は [補完のみの画像](../builds/seamless/backdrop_coverage.png) と [読み込み失敗時の画像](../builds/seamless/failure_coverage.png)。フレーム測定は起動準備後に行い、サンプル数もJSONへ記録する。元の白い陸地マスクを使用すると失敗する既知の陸地点も、画像の色で検査する。

|項目|PCでの測定例|
|---|---:|
|地図被覆欠落|0フレーム|
|100ms超の計測区間|0|
|フレーム間隔p95|約27ms|
|フレーム間隔p99|約38ms|
|フレーム間隔最大|約66ms|
|可視更新・ストリーム要求反映のメインCPU時間p95|約2.6ms|
|同時CPUジョブ数の観測最大|3（設定上限4）|

上記のメインCPU時間は `main_map.gd` の可視更新とタイル反映の範囲であり、エンジン全体・全描画・全スレッドのCPU時間ではない。PC上では旧版の別プロセスも動作していたため、隔離した性能保証値ではない。再実行の正確な値はJSONに残す。

追加で、破線の端数回帰、GPU上の破線／空白の画素、400%ズーム、タイルストリーミング、湖の地表追従・独立切り替え、道路接続、ログの停止中保存・容量交代・遅いディスクに対する非同期性、ワーカー実行中の終了を確認した。背景移行・復帰と低メモリ通知もコード上で注入して検査する。

Windows配布PCKの実描画でも、被覆欠落0・100ms超0、p95 27.87ms・p99 42.55ms・最大64.52ms、主更新p95 2.36msを記録した。Windows実行ファイルを600フレーム起動し、`map_ready` と正常終了ログ、終了コード0を確認。Android APKは署名v2/v3の検証に合格した。Androidのエクスポートにはプロジェクトアイコン未指定のメッセージが残るが、APKの生成・署名検証は完了している。

## 残る実機検証・範囲

- Android端末は未接続。実機のPSS 300MiB以下、発熱、消費電力、30分巡回、タッチ操作、低〜中位端末での30fpsは未検証。PCの数値をスマホの達成値として扱わない。
- 管理予算は資産ペイロードと作業領域の見積もり。Godotの管理オブジェクト、フォント、ドライバの内部確保等をすべて表す実メモリ上限ではない。OSのメモリ測定が引き続き必要。
- 巨大な全国図を全精細度で常駐させる方式ではない。容量不足や初めての場所への移動では、詳細が揃うまで地形が粗く見える。
- すべてのGPU処理が1.5ms以内という保証ではない。実機の単発アップロードが長い場合は、その資産をさらに分割して調整する。
- 起動時の必須全国図が欠損・不整合なら、エラーを記録してマップ操作の開始を中止する。起動後の通常の詳細読み込み失敗では常駐全国図を維持する。

## 再生成と再検証

元の地形・境界を変更した場合は従来の生成処理の後、必ずシームレス用派生資産を生成する。

```powershell
godot_console --headless --path . --script res://tools/godot/build_map_runtime.gd
godot_console --headless --path . --script res://tools/godot/build_seamless_runtime.gd
python -m unittest discover -s tests/base_map -p test_seamless.py -v
python -m unittest discover -s tests/base_map -p test_zoom_freeze.py -v
godot_console --path . --script res://tests/base_map/godot/test_seamless_map.gd -- --district-unconfirmed
godot_console --path . --script res://tests/base_map/godot/test_dash_shader.gd
```

内部パネルを使う既存検証は `-- --developer-ui` を併用する。水系等の非同期化に合わせ、テスト側も処理完了を待ってからデータを検査する。

配布先：`builds/windows-seamless/MyWorldsOnFreedom.exe`、`builds/android-seamless/MyWorldsOnFreedom.apk`。未確定郡を含むプリセットで生成する。Android APKは実機確認用のデバッグビルド。
