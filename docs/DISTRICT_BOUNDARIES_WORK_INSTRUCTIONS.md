本書では依頼中の「群」を、国の下位に置く「郡」と解釈する。後続の依頼により工程A・Bの初回調査、工程Cの比較候補作成、工程Dの親領域内の閉区画作成を実施した。既存の国境、城、道路、配布版は変更していない。

## 1. 完成させるもの

各国について、郡名・異称・対象年代・根拠資料を整理し、郡の境界、選択用の面、国との親子関係を作る。地図では国と郡の表示・選択を切り替え、城や集落がどの郡に属するか調べられるようにする。

郡はゲーム内の地域・行政区画の基礎単位として扱う。郡をそのまま戦国大名の領国、城の支配圏、徴税単位、軍事指揮系統と同一視しない。荘園・郷・領主支配・係争関係は関連情報として保持し、郡の面とは別に扱う。

初版の成果物は次の6点。

1. 国別の郡候補一覧と、採用・保留・対象外の理由。
2. 使用資料、資料年代、参照箇所、利用条件、判断根拠の台帳。
3. 郡の面と共有境界を一元管理する編集正本。
4. 描画・クリック・隣接関係・拠点所属用の派生データ。
5. 平面・立体・400%表示の比較画像と、境界・所属の検証記録。
6. 国別進捗と、未確定範囲を隠さない残件一覧。

郡数の全国目標や各国の均等な分割数は先に決めない。資料から確認した区分を採用する。

### 現在の国区分と歴史上の国区分の違い

現行レジストリには `honshu-area-*` のIDや、陸前・陸中・磐城・岩代・羽前・羽後などの表示名がある。現在の66領域を「1582年の令制国66か国」と読み替えない。旧来の [国境作業指示書](SENGOKU_POLITICAL_BOUNDARY_WORK_INSTRUCTIONS.md) と現行データが一致しない点も記録する。

本工程では現行の親領域を保持し、以下を別々に管理する。

- `parent_region_id`：現在のゲーム内国レジストリのID。
- `historical_province_id`：対象年代の史料上の国に対する調査ID。
- `district_entity_id`：史料上の郡を表すID。
- `district_region_id`：ゲーム内で一つの親領域に属する郡の表示区画ID。

史料上の同じ郡が現行の親領域をまたぐ場合、同一の `district_entity_id` を参照する表示断片を作り、`fragment_reason=current_parent_partition` を記録する。これは歴史上の郡の分裂を意味しない。画面では必要に応じ「○○郡（表示範囲）」と説明する。親の国区分自体を改訂する提案は、差分を別途まとめ、本工程で無断修正しない。

現行の親領域がない離島や蝦夷地などには、郡だけを先行して作らない。対象外・未収録を区別して一覧に残す。

## 3. 調査資料と時代差の扱い

### 3.1 資料の使い分け

|資料|用途|注意点|
|---|---|---|
|対象時期に近い文書、郡名・村郷名の記録、境界争論・検地関係史料|名称、所属、境界の根拠|刊行年と史料の対象年を別記。地名だけで面の境界は確定しない|
|自治体史、博物館・教育委員会の調査、歴史地名辞典|郡の変遷、村郷・荘園の比定、一次史料の所在|解説が示す年代と根拠を確認する|
|国絵図・郷帳|郡と村の関係、隣接関係、概略位置の比較|江戸期の状態を1582年に自動適用しない|
|幕末・明治の旧郡境界、行政区域変遷データ|後世の形状候補、改編履歴の照合|参考年代の形状として保存し、時代補正が済むまで本番採用しない|
|現代の地形・水系・地名|位置合わせ、地形と史料の対応の検討|現在の川筋・市町村界が当時の郡境だったとは限らない|

国立公文書館の説明では、国絵図は慶長・正保・元禄・天保の各期に作成され、元禄図には郡別の色分けがある。これは後世の比較資料として利用する根拠になるが、1582年の直接資料ではない。[国立公文書館・元禄国絵図](https://www.digital.archives.go.jp/DAS/pickup/view/category/categoryArchives/0300000000/0301000000/01)

歴博の旧高旧領取調帳は江戸期の国・郡と村名、旧領、石高等を収録する。郡の面を直接確定するデータとしては扱わない。[歴博・データベース概要](https://www.rekihaku.ac.jp/doc/gaiyou/kyuudaka.html)

日本荘園データベースの郡欄は原則として『和名類聚抄』の区分で、中世の所属と一致しない場合があると提供元が説明している。郡名を抽出する際は、記録の区分体系を必ず確認する。[歴博・項目説明](https://www.rekihaku.ac.jp/help/getdoc_syoen.html)

### 3.2 既存の郡ポリゴンを取り込む前の確認

CODHの旧国・旧郡境界データセットは、幕末の国境・郡境を取り出したものとして公開されている。全国の形状候補を調べる入口として有用だが、そのまま1582年版にはしない。提供ページにはCC BY-NCと商用利用の問い合わせ先が記載されているため、配布用データに取り込む可否を確認してから利用する。[CODH・旧国・旧郡境界データセット](https://geoshape.ex.nii.ac.jp/kg/index.html.ja)

1889年以降を対象とする歴史的行政区域データセットも、時代補正の比較用とする。[CODH・歴史的行政区域データセット](https://geoshape.ex.nii.ac.jp/city/)

参照、画像保存、データ抽出、直接トレース、派生形状の配布を区別し、資料ごとに利用条件と実際に行った処理を記録する。別形式への変換や手動トレースによって元資料の利用条件が消えるとは扱わない。条件未確認の形状は作業用領域に置き、配布対象へ自動コピーしない。問い合わせや外部への連絡は別途ユーザーの指示がある場合に行う。

### 3.3 年代を補正する順序

1. 対象時点の郡名・異称・国所属の一覧を作る。
2. 郡の成立、廃止、分割、合併、改称、国をまたぐ所属変更の履歴を調べる。
3. 史料上の村・郷・荘園等を対応付け、所属の根拠を記録する。
4. 既知の所属地点と矛盾しない範囲で、境界の候補を検討する。
5. 後世の境界を採用する場合は、継続と判断した根拠、変更を戻した箇所、未確認箇所を区間ごとに記録する。

資料間の不一致を単純な多数決で解消しない。成立年代、独立性、記述範囲、位置精度を比べ、採用しなかった説も残す。

## 4. 確定できない郡境をどう表すか

郡の存在、名称の同定、所属、境界の位置、ゲームへの採用は独立した状態として管理する。画面で一本の線を引けても、史実として確定したという意味にはしない。

|項目|例|
|---|---|
|`existence_status`|`supported` / `inferred` / `unconfirmed`|
|`geometry_status`|`source_supported` / `reconstructed` / `game_estimated` / `unlocated`|
|`adoption_status`|`draft` / `accepted` / `held` / `excluded`|
|`temporal_basis`|`near_target` / `retrospective` / `later_comparison` / `unknown`|

`source_supported` は根拠資料があることを示し、測量精度を保証する値ではない。境界区間ごとの根拠・精度を持たせ、郡全体を一律に「正確」としない。

- 名前と所属だけ確認できた郡は、形状を空のまま台帳に登録できる。
- 未確定範囲は「郡未確定」の領域として保持し、架空の郡名を付けない。
- ゲーム用に閉じた区画が必要な場合は、根拠のある端点間を地形等から推定して `game_estimated` とする。対象範囲、選択理由、代替案を残し、破線表示・詳細説明を行う。
- ボロノイ、等面積分割、城からの最短距離、現代市町村界だけで史実の郡を自動生成しない。
- 推定候補は比較可能な状態まで作成できる。史料不足を理由に国全体の調査を止めず、他の郡・国の作業を進める。

以下は全工程で用いる構成。工程A・Bでは `data/sources/districts/`、`data/editorial/districts/`、`docs/districts/` を作成済み。境界正本・実行時データ・画面機能は未作成であり、編集台帳のうち境界判断・拠点所属判断も後続工程で追加する。

  settlement_membership.json        拠点所属と確度

### 必須属性

郡実体は `district_entity_id`、名称、異称、読み、史料上の国、対象期間、上記の確度・採否、出典参照、判断理由を持つ。同名郡を名称だけで統合しない。外部データセットのIDは別属性で保持する。

表示区画は `district_region_id`、`district_entity_id`、`parent_region_id`、複数ポリゴン・内周、構成共有辺、名称表示点、境界不確実性、生成元の版を持つ。島や飛び地は一郡の複数面として保持でき、連結のための陸地を作らない。

共有辺は一つの `boundary_id` につき一つの形状を持ち、左右の表示区画ID、根拠、境界種別を保存する。親国境・海岸線と一致する区間は既存の境界ID・区間参照を使用する。片側の郡を編集しても二重線や隙間ができない構造にする。

編集用の投影・単位は地図基盤の定義を使用し、経緯度のまま距離や面積の許容値を計算しない。実行時への変換は既存の8192座標への変換を一回だけ適用する。IDの再採番によって他データの参照を壊さない。

## 6. 作業順序

### 工程A：対象国と依存関係を固定する

現行レジストリの全親領域を列挙し、表示名・ID・入力版・史料上の国との対応・対象内外・調査状態を保存する。名前の一致だけで外部の国IDを結び付けない。未収録の国や親領域外の島は別の残件とする。

### 工程B：郡台帳と資料台帳を作る

各国の候補を一巡し、名称、時代差、典拠、利用条件を記録する。名称の存在と位置の根拠を分け、各判断から参照ページ・図版・文書番号へ戻れるようにする。後世の資料しかない国も、そのことが分かる台帳を作る。

### 工程C：位置合わせと境界候補を作る

資料の原図と作業用の補正結果を別々に保存する。地名・寺社・峠・合流点などの対応点に根拠を付け、基準地図との残差を記録する。現在の河道や海岸に一致しないことを理由に、史料全体を強制的に変形しない。

元資料が広い線や曖昧な色分けの場合は、不確実性を幅・注記として保存する。400%で見えることを理由に、資料にない細かな屈曲を足さない。郡の区画候補は、同じ国の全郡を一つの共有境界網として編集する。

### 工程D：現行の国の内部で区画を閉じる

郡候補を親国の面へクリップし、既存の親国境・海岸線を外周として再利用する。外部資料の国形状と現行国の形状との差は、差分面と修正理由を残す。大きな差を一括吸着で消さない。

候補間の重なりや資料のない隙間はレビュー対象にする。微小な数値誤差の補正と、歴史判断を要する境界移動を別処理にする。判断待ちの部分は未確定領域で埋め、確認済みの郡を不自然に拡張しない。

閉じた後は、同じ共有辺から面・線・隣接関係を再生成する。点で接するだけの郡と、一定長の境界を共有する郡は隣接属性を分ける。

### 工程E：拠点・道路との対応を作る

254拠点について、登録座標が含まれる表示区画を計算し、史料上の所属と照合する。描画用の記号位置や推定連絡路の出入口を、城そのものの郡所属判定に使わない。

郡境上、境界付近、位置が未確定、簡略海岸の外側などの場合は `ambiguous` または `unresolved` とし、候補郡と理由を保持する。最近傍の郡へ無条件に割り当てない。位置の根拠から見て史料所属と面判定が食い違う場合は、個別判断を保存する。

推定連絡路は形状を変えず、所属郡の通過順と境界通過点を別ファイルへ派生させる。郡境を越えたという理由だけで関所、移動不可、通行税、敵領判定を加えない。隣接は交通の接続とは別であり、海峡を挟む区画を陸路で結ばない。

### 工程F：ゲーム内表示・選択を追加する

`district_layer.gd` 等の独立レイヤーを新設し、背景タイルや国の元データを上書きしない。表示・選択に必要な範囲だけを扱う空間索引を持たせる。

- 「郡境」の表示切替と、「国を選択／郡を選択」のモードを設ける。
- 全国表示では国境を優先し、郡名・細線は抑制する。拡大時に郡境・郡名を表示する。
- 国境は郡境より明瞭にし、同じ位置の線を二重描画しない。
- 推定境界は破線などで区別する。名称・確度・出典は詳細欄でも確認できる。
- 郡名の代表点は面の内側に置き、穴・海・別郡へ置かない。文字の衝突は一覧検索で補う。
- 郡を選ぶと、国名、郡名、対象年代、採否・確度、所属拠点、史料と残件を表示する。
- 境界付近のクリックは線への許容距離で候補を集め、表示上の郡ラベル位置が最も近い一郡へ決定的に割り当てる。
- 平面・立体で同じ地表ポリゴンを使用する。線は既存の `project_line`、塗りは地表三角形に沿う分割を使用し、クリックは既存の逆変換で地表へ戻して判定する。
- 400%まで、線幅とラベルサイズを画面基準で調整する。郡境のためにズーム上限を変更しない。

### 工程G：国ごとに検証して取り込む

国別の候補図、時代補正の一覧、検査結果、既存国との差分をまとめる。採用判断が必要な推定や国対応の問題は、具体的な比較案を用意して提示する。通常の変換・検証・不具合修正のたびに承認待ちにはしない。

採用した国だけを実行時データに組み込み、保留形状が紛れ込まないようにする。国ごとの成果を独立して再生成・差し戻しできる単位で管理し、既存の採用済み国の郡境を無関係な修正で変更しない。

## 7. 最初の試作と全国展開

最初の試作は **和泉 → 摂津 → 河内 → 大和** の順を基本とする。近接する4国で、海岸、国境、内陸、既存拠点所属、400%表示を比較しやすいためであり、史料が最も揃っていると断定するものではない。

岸和田城・石山本願寺・高屋城・筒井城の所属は確認対象にするが、城を中心に郡境を作らない。石山本願寺等のゲーム用採用例外を、郡の歴史的存在の根拠にしない。

4国でデータ形式と表示を検証した後、残りの現行親領域を近畿周辺、東海・甲信、北陸、関東、中国・四国、九州、東北の地域単位で進める。資料の入手状況により地域順は変更できる。東北等の親国対応の調査は早期に並行して行い、名称対応の問題を最後まで放置しない。

全親領域に「未着手／調査中／形状作成中／部分採用／採用／保留／対象外」を付ける。一地域の完成を全国完成と報告しない。

## 8. 検証基準

幾何の数値検査は実行時と同じ8192座標系でも行う。線の一致の数値許容を `1e-5` 座標単位、面の差分許容を一国あたり `1e-4` 座標単位²から開始し、採用した丸め精度と一緒に設定へ記録する。これは計算誤差の検査値であり、史料や境界の位置精度を意味しない。

|検査|合格条件|
|---|---|
|入力保全|陸地、国レジストリ、拠点、道路、標高、座標変換の入力ハッシュが変わっていない|
|参照整合|IDが一意。親国・郡実体・共有辺・出典・拠点の参照先が存在する|
|形状健全性|自己交差、NaN、無効な穴、ゼロ長の辺、不正な面がない|
|親国との整合|全表示区画が親国の内側。親国からはみ出す差分が許容値以下|
|国の被覆|郡の面と明示した未確定面の和集合が親国と一致。説明のない穴・重複がない|
|共有辺|隣接面が同じ辺を逆向きに参照。国境・海岸線を重複保持・二重描画しない|
|島・飛び地|資料と親領域で扱う陸地片を失わず、海を埋める接続面がない|
|史料・年代|全採用実体・境界に根拠と対象年代があり、後世比較を直接確認と表示していない|
|拠点所属|全対象拠点に確定・候補複数・未確定のいずれかを付与。表示上の移動で整合させていない|
|道路|既存のルート形状と到達性が維持され、通過順が実形状との交差順に一致|
|表示・選択|平面・立体で同じ郡を選択でき、国／郡モードと郡境非表示が独立して機能する|
|400%|二重線、タイル境界の偽線、選択塗りの浮き、ラベルの顕著な重なりがない|
|性能|全国／試作4国／400%でフレーム時間・読込件数・メモリを変更前と比較し、値と実行環境を記録する|
|配布|採用データだけを収録し、利用条件・帰属が記録された状態で新規起動できる|

国ごとのレポートには、採用郡数、未確定面積と国に対する割合、推定境界の長さ、所属不明拠点数、資料の年代分布を載せる。未確定領域を含めた幾何の被覆完了と、歴史調査の完了を別に判定する。

## 9. 完了条件と次に行う作業

この手順書の完成後、実装工程で最初に行うのは「現行親領域一覧・史料上の国との対応表」と「試作4国の郡候補・資料一覧」の作成。その次に、試作1国の境界候補と画面比較へ進む。全国の郡境を推測で先に引かない。

初版の実装完了は、対象とした国の一覧、採用した郡・保留した郡、未確定範囲、検査結果、出典、再生成手順、実行時の確認画像が揃い、指定した範囲の郡選択が動くこととする。資料不足が残る場合は「部分採用」と明示し、未確定面を含むだけで史実の全国郡境が完成したとは報告しない。
