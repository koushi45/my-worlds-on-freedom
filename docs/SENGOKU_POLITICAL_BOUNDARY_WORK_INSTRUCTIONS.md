# 戦国期・令制国政治境界レイヤー作業指示書

作成日: 2026-09-07  
対象基盤: `japan_land` 版 `1.0.0`  
状態: **作業手順確定／境界データ未作成**

## 1. 目的と今回の範囲

承認済みの日本陸地正本 `japan_land` に、指定された令制国地図を根拠とする戦国期向けの国境レイヤーを重ねる。クリック判定、通常表示、選択表示、5段階LODは、最終承認された同一の政治領域・共有境界・海岸線参照から派生させる。

今回作るものは令制国の地理境界であり、戦国大名の実効支配域ではない。大名勢力圏、郡境、城領、飛び地、係争地は別の年代別レイヤーとして後工程で扱う。

| 項目 | 内容 |

| 用途 | 令制国名、隣接関係、内陸境界形状をトレースする基準画像 |
| 指定画像 | [1280px版](https://thumb.wikimedia.org/wikipedia/commons/thumb/9/9b/Ancient_Provinces_of_Japan_Ryoseikoku_Map.png/1280px-Ancient_Provinces_of_Japan_Ryoseikoku_Map.png) |
| 原典ページ | [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Ancient_Provinces_of_Japan_Ryoseikoku_Map.png) |
| 作者表示 | Artanisen。現行版には、まいまいようおによる修正履歴がある |
| ライセンス | CC BY-SA 4.0 |
| 指定版の寸法 | 1280 × 1341 px |
| 原画像の寸法 | 3031 × 3176 px |

指定された1280px版を「画像上の線をどれと判断したか」の基準版として固定する。作業時にはクエリー文字列を除いた上表のURLから取得し、取得日、HTTP最終更新情報、ファイルサイズ、SHA-256を `source_manifest.json` に保存する。取得後のファイルを無断で差し替えない。

原画像は細部の判読補助に限り使用できる。ただし、1280px版と原画像で線の解釈が異なる場合は自動的に原画像へ切り替えず、差分を提示して承認を受ける。

### ライセンス上の必須処理

この画像から直接トレースした境界ベクターは、画像を基にした改変物として扱う前提で管理する。少なくとも次を実施する。

- 作者、原典ページ、CC BY-SA 4.0へのリンクをゲーム内クレジットと配布物へ記載する
- 境界をトレース・位置補正・クリップしたことを明記する
- 指定画像、トレース正本、帰属文、ライセンス写しを同じソースパッケージで管理する
- 再配布時の継承条件を満たせる形式で境界派生成果物を分離する
- 商用配布前に、境界派生成果物とゲーム全体のライセンス上の関係を法務確認する

本書は法的助言ではない。ライセンス条件に同意できない場合は実装を開始しない。

## 3. 時代補正ルール

Commonsの説明では、実線は鎌倉期から明治維新までの旧国境を示し、破線には1869年の北海道11か国、陸奥・出羽の再分割などが含まれる。戦国期レイヤーでは次のルールを固定する。

1. 本州・四国・九州と主要島の実線境界を令制国境候補として採用する。
2. 1869年以後を示す破線は採用しない。
3. 陸奥は戦国期の1国、出羽も戦国期の1国として扱い、明治期の分割線を生成しない。
4. 北海道11か国は生成しない。蝦夷地をゲーム対象に含める場合は `ezo` または `unassigned` とし、別途承認を受ける。
5. 南西諸島は現在のゲーム対象外とし、政治領域を生成しない。陸地正本からは削除せず `out_of_scope` とする。
6. 対馬、壱岐、佐渡、隠岐、淡路など、ゲーム対象に含まれる旧国は保持する。
7. 画像だけで判断できない境界は補間、ボロノイ分割、現代行政界による穴埋めをせず `unconfirmed` とする。

実装開始前に、対象年、蝦夷地の扱い、南西諸島の対象外指定、旧国一覧を承認記録へ残す。

## 4. 正本と派生物の関係

指定画像は政治境界の参考正本であり、日本の海岸線正本ではない。画像の海岸形状で `japan_land` を変形・上書きしてはならない。

```text
japan_land_master.gpkg / japan_land
  └─ 唯一の陸地・海岸線正本

指定令制国画像
  └─ 国名・隣接関係・内陸境界のトレース根拠

画像トレース境界 + japan_land
  └─ historical_region = traced_region ∩ japan_land_master
      ├─ political_regions_master.gpkg
      ├─ shared_boundaries_master.gpkg
      ├─ coastline_references.json
      ├─ click_masks（判定専用）
      └─ political LOD 0～4
```

海に接する国の外周は画像からトレースせず、既存の `coastline_master` の区間IDを参照する。これにより通常海岸線、国選択輪郭、クリック領域の海岸側が同じ陸地正本へ一致する。

## 6. フェーズP0：取得・記録

1. 指定1280px画像を取得し `ryoseikoku_1280.png` として保存する。
2. SHA-256、ピクセル寸法、色形式、取得URL、取得日時を記録する。
3. Commons原典ページの作者、説明、版履歴、ライセンスを保存する。
4. 配布用の日本語・英語の帰属文を作る。
5. 画像ファイルを改変禁止の入力として読み取り専用扱いにする。

検証ゲートP0では、画像ハッシュ、寸法、ライセンス文、帰属文が揃うまでトレースを開始しない。

## 7. フェーズP1：画像座標での直接トレース

画像を先に日本座標へ一括変形してから線を抽出しない。まず1280×1341の画像ピクセル座標上で、国境線の中心を直接トレースする。

### トレース規則

- 1本の共有国境は1本のLineStringとして作り、両国が同じ線IDを参照する
- ポリゴン外周を国ごとに二重トレースしない
- 線幅の左右端ではなく視覚上の中心線を取る
- 海岸線、文字、番号、引出線、破線の明治期境界を国境として拾わない
- 交差点は共通ノードへスナップし、T字接続や多国接点を明示する
- 線が隠れている箇所は推測せず、両端を `unconfirmed_endpoint` として止める
- 自動抽出を使う場合も、最終線は人が原寸・200%・400%で確認する

### 必須属性

| 属性 | 内容 |
|---|---|
| `boundary_id` | 永続ID |
| `left_region_id` | 片側の旧国ID |
| `right_region_id` | 反対側の旧国ID |
| `source_pixel_start` | 始点の画像座標 |
| `source_pixel_end` | 終点の画像座標 |
| `certainty` | confirmed / probable / unconfirmed |
| `trace_method` | manual / assisted |
| `review_status` | pending / accepted / rejected |
| `note` | 隠れ、破線、判読不能等 |

中心線誤差は、判読可能区間で原画像表示上0.75px以内を目標とする。線そのものが太い・不明瞭な箇所は数値で合格扱いにせず `probable` とする。

## 8. フェーズP2：地域別ゴムシート補正

指定画像は地理座標を持たず、基盤地図とは海岸形状と投影が異なる。そのため、日本全体への単一アフィン変換は禁止し、地域別の局所変換を行う。

### 対応点

最低限、次を独立した補正単位として扱う。

- 北海道・東北
- 関東
- 北陸・甲信越
- 東海
- 近畿
- 山陰
- 山陽
- 四国
- 北部九州
- 中南部九州
- 対馬・壱岐・佐渡・隠岐・淡路

各単位で、岬、湾奥、海峡、島端、湖、明瞭な多国接点などに多数の対応点を置く。対応点は `control_points.gpkg` に画像座標、8192正本座標、根拠、採否、残差を保存する。

### 変換方式

1. まず区分線形変換を試す。
2. 対応点間で急な折れや反転が出る場合だけTPSを比較する。
3. 採用方式は地域ごとに固定し、パラメータとライブラリ版を保存する。
4. `japan_land` や海岸線側は一切変形しない。
5. 変換後に線が海へ出た場合、海岸へ機械的に全点スナップせず、端点付近だけをレビューする。

対応点の残差目標は、中央値1.5入力px以下、95パーセンタイル4入力px以下とする。ただし、この値は位置合わせの品質指標であり、歴史的正確性を保証しない。

## 9. フェーズP3：政治領域の構築

変換済み共有境界を、`japan_land` の外周および島構成と合わせて平面グラフ化する。閉じた面だけを旧国ポリゴン候補とする。

```text
political_region = traced_historical_region ∩ japan_land_master
```

### 構築規則

- 内陸側は承認済み共有境界だけを使う
- 海側は `coastline_id` と区間参照で閉じる
- 湖岸は湖IDを参照し、海岸IDへ混ぜない
- 画像海岸線を政治領域へ複製しない
- 隣接国名リストと実際のグラフ隣接を照合する
- 飛び地や島所属は個別のpartとして同一 `region_id` にまとめる
- 未確定線を含む面は `certainty=unconfirmed` のままにする
- 微小隙間をbuffer、snap、ボロノイで自動的に所有国へ配分しない

## 10. フェーズP4：手動レビュー

次の比較画像を全国および地域別に生成する。

1. 指定画像と画像座標トレースの重ね合わせ
2. 変換後境界と `japan_land` の重ね合わせ
3. 国別半透明塗り分け
4. 隣接関係エラー表示
5. 重複、隙間、自己交差、未閉鎖面の強調表示
6. `unconfirmed` 区間と端点一覧
7. 海岸線参照区間の色分け

レビューは九州、四国、中国、近畿、東海、関東、甲信越・北陸、東北、主要離島の順で行う。各地域はユーザー承認後に `accepted` とし、未承認地域を全国版へ混在させない。

## 11. 検証ゲートP：政治正本承認

自動検査で次を満たす。

- 全ジオメトリが妥当で、NaN、空形状、自己交差が0件
- 異なる国ポリゴン間の面積重複が0
- 承認済み対象陸地に説明のない隙間が0
- 対象外、未確定、蝦夷地は明示的な状態として記録される
- 共有国境は隣接する2国だけから同じ `boundary_id` で参照される
- 海岸部分の座標複製が0で、すべて既存 `coastline_id` を参照する
- 交差ノードで未接続端点が0。ただし `unconfirmed_endpoint` は監査一覧へ残す
- 国名から定義した隣接表と幾何学的隣接表が一致する
- GeoPackageとGeoJSONミラーの地域数、構成数、面積が一致する
- 同じ入力ハッシュと設定から再生成した成果物のSHA-256が一致する

承認結果、版番号、画像ハッシュ、陸地正本ハッシュ、承認地域、未確定箇所を `political_master_manifest.json` に記録する。承認前にクリック判定やゲーム表示を作らない。

## 12. フェーズP5：クリック判定と選択表示

クリックマスクは政治正本から生成する判定専用データとし、画面へ描画しない。

```text
selection_outline = shared_boundary_ids + coastline_references + lake_references
```

- クリック時は国IDと国名を表示する
- 選択輪郭をクリックマスクの外周から逆生成しない
- 選択輪郭の内陸側は通常表示と同じ共有境界IDを使う
- 選択輪郭の海側は通常表示と同じ海岸線ID・点列を使う
- 境界上のクリックは、選択候補2国を返せるようにする
- `unconfirmed` 国はUIへ「境界未確定」と表示する

## 13. フェーズP6：5段階LODとタイル

LOD 0～4は承認済み政治正本から一方向に生成する。LODごとに画像から線を再抽出しない。

| LOD | 用途 | 処理方針 |
|---:|---|---|
| 0 | 全国 | 共有トポロジーを維持した強めの簡略化 |
| 1 | 地方 | 国形状が識別できる簡略化 |
| 2 | 地域 | 主要屈曲を保持 |
| 3 | 狭域 | 軽微な簡略化 |
| 4 | 詳細 | 正本点列、または表示に必要な最小限の簡略化 |

隣接国の境界を別々に簡略化せず、共有境界を1回だけ簡略化して両国から参照する。海岸側は既存の対応LOD海岸線IDを使用する。タイル境界で線を分割する場合もグローバル8192座標を保持し、隣接タイルの端点を同一値にする。

## 14. Godotへの組み込み

描画順序は次の通りとする。

```text
地図テクスチャ
  → 通常海岸線
  → 令制国共有境界
  → 選択中の国輪郭
  → 城などのゲーム要素
  → UI
```

政治境界は現在の可視タイルとLODだけをロードする。クリック用データは空間インデックスで可視周辺だけを検索し、全ポリゴンを毎フレーム走査しない。真上表示データだけを保存し、斜め表示では既存の表示変換を実行時に適用する。

## 15. 必須テスト

- 指定画像のハッシュ固定とライセンス資料の存在
- 画像座標トレースが線中心から許容値以内
- 地域別変換の対応点残差と三角形反転が0
- 政治領域が `japan_land` 外へ出ない
- 地域間重複が0
- 未説明の隙間が0
- 共有境界の重複線・往復線が0
- 国名による隣接表と幾何学的隣接表が一致
- 通常境界と選択境界のIDが同一
- 海岸側選択線と通常海岸線の点列IDが同一
- クリック地点が返す国IDと表示対象国IDが一致
- 5段階LODとタイル継ぎ目で境界接続が切れない
- LOD切替時に国境が別の位置へ飛ばない
- 画面外の政治タイルが描画されない
- Windows、Android、iOS、WebでJSON・ベクター・クリックデータを読み込める

## 16. 作業順序と停止条件

```text
P0 画像・ライセンス固定
  → P1 画像座標で中心線トレース
  → P2 地域別ゴムシート補正
  → P3 政治領域・共有境界・海岸参照の構築
  → P4 地域別手動レビュー
  → 検証ゲートP・ユーザー承認
  → P5 クリック判定と選択表示
  → P6 LOD・タイル
  → Godot統合・各プラットフォーム試験
```

次の場合は作業を停止し、推測で進めない。

- 画像またはライセンスの取得記録が固定できない
- 戦国期と明治期の線を判別できない
- 国名または隣接先を確定できない
- 地域変換で線の反転、交差、過大な残差が生じる
- 海岸線を画像側から作り直す必要が生じる
- 未確定箇所を埋めなければ面を閉じられない
- 地域別レビューが未承認

## 17. 最初に実施する作業

実装開始時はP0とP1の九州地方だけを行う。指定画像の固定、帰属資料作成、九州の共有境界中心線トレース、国名・隣接表の作成までで停止し、変換前の画像座標トレース比較画像をユーザーへ提示する。承認後に九州の地域別位置合わせへ進む。
