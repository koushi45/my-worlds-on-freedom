実施日：2026年10月2日〜3日。[区画化の結果](TERRAIN_CHUNK_OPTIMIZATION_RESULTS.md)に続く変更。キャッシュ上限は64区画のまま維持した。

- `source.zip`：ソース、資産、ドキュメント、未コミットの変更を含む作業ツリー。ビルド出力、Godotインポートキャッシュ、Git内部、依存環境キャッシュは除外。

元の実行版はバックアップの `windows-release/MyWorldsOnFreedom.exe` から起動できる。今回の新しい地形資産は別ディレクトリへ保存し、従来の地形資産を上書きしていない。

## 実装

1. 地形の2×2セルを、境界の頂点と中央の頂点を使う三角形へまとめる。不要になった頂点と三角形を配列から取り除く。残す頂点の標高・法線・UVは元の値を使用する。
2. 平坦部は、標高の補間との差が3m以内、法線の上向き成分が0.97以上、法線の補間差が0.01以内の場合にまとめる。三角形間の高さの誤差は元の補間との差の最大2倍が保守的な上限となる。近景と遠景の通常メッシュに適用する。
3. 区画の端は元の全頂点を残す。細かいセルとの接続にも中間頂点を残し、不連続な接続を防ぐ。遠景では128ワールド単位の格子線も保持し、移動先の近景の外周がどこへ来ても元の16単位の辺に接続できる。
4. 遠景は、より広い標高差64m・法線差0.04を許容した候補も制作する。候補の高さの差とカメラの投影から、地形と影の位置のずれの上限を物理ピクセルで見積もる。0.35px以下なら粗い候補へ切り替え、使用中は0.5pxを超えた場合に細かい方へ戻す。地形の色・照明差まで0.5pxで保証する判定ではない。
5. 富士の専用メッシュとその周辺を間引き対象から外す。標高の元データ、画像、素材、影設定は変更しない。
6. 通常・遠方のメッシュは別ファイルとし、使う方だけを読み込む。両方を常時保持しない。切り替えは同じ描画ノードのメッシュ交換で行う。
7. 近景は生成ジョブ内でまとめる。元の細かい頂点で標高・法線を評価するため、CPUの標高評価数を減らす方式ではない。不要な元のインデックス生成を省き、作業用の高さ配列も間引き前に解放する。同時2ジョブ、1件768 KiBの推定予約を既存CPUジョブ管理で扱う。

平坦部では格子の辺の間隔が近景2→4、遠景16→32ワールド単位になる箇所がある。ただし、中央点と接続に必要な点を残すので、一律に4／32単位の格子へ変えたものではない。

全国64区画の頂点合計は、従来270,400、平坦部をまとめた通常版185,294（約31.5%減）、遠方候補182,715（約32.4%減）。これは制作済み全区画の合計であり、実行中は必要な区画と選ばれた候補だけを保持する。遠方候補の上乗せ削減は小さく、主な削減は平坦な面の間引きによる。

## 検証

- 平坦な面の頂点・三角形の削減、急斜面の密度維持、保護領域の維持、三角形の向き・面積、区画内に開いた辺がないことを自動確認。
- 128単位の接続線に元の16単位の頂点が残ることを確認。
- 近景で残した頂点の位置・法線・UVが元の細かい格子と一致。移動後の8区画の再利用、回転時の生成抑止、低倍率での解放も確認。
- 800%の3地点×4方向と50%の広域表示の13画面を比較。時刻・水面の描画を固定し、従来の一枚メッシュを参照とした。
- 全13画面で平均RGB絶対差は255段階中0.018未満。RGBのいずれかの差が32を超える画素は最大約0.00154%。設定した確認基準は平均差1.0以下、大きな差の画素0.5%以下。画像の完全一致ではない。
- 差が最大の画像も目視確認し、試験した画面で地形の穴や大きな輪郭崩れは確認していない。任意の視点・倍率すべての保証ではない。
- カメラ・ズーム・回転、地形上の描画とマーカーの整合、照明の回帰試験に合格。レイの画面上の誤差約0.00275px、ズーム固定点の誤差約0.00706px。
- 480件の地形レイ判定、静止時のHUDと地図マーカー、イベントによる更新の回帰試験に合格。クリックと遮蔽判定は元の細かい標高の三角形を引き続き使う。簡略表示の表面への厳密な交差判定へ変更したものではない。

画像と比較指標：`builds/performance_800/adaptive_visual/`。回帰試験：`test_terrain_adaptive.gd`、`test_terrain_chunks.gd`、`test_map_view_angle.gd`、`test_map_optimization.gd`。

## Windowsリリース版の測定

**頂点数の削減は確認できたが、CPU・fpsの一貫した改善は確認できなかった。800%で移動・回転中の60fpsも未達である。**

Windowsリリース版の書き出しに成功し、通常起動と、書き出したPCK内の地形読み込み・再利用・距離判定の試験に合格した。

同じ最終実行ファイルで、通常起動の間引き版と `--uniform-terrain` の均一間隔版を続けて測定した。Godot 4.7.2 Compatibility、i7-12700F、RTX 4060、1920×1080、800%、視点角15度、最大60fps、VSync無効。日付進行を止め、素材読み込み後に半径160の円移動と360度回転を各120フレーム計測。経路はフレーム数に対して固定し、実時間の移動速度を固定した試験ではない。

| 地点・操作 | 均一間隔fps | 間引き版fps | 均一間隔p95 | 間引き版p95 |
|---|---:|---:|---:|---:|
| A 移動 | 30.69 | 29.63 | 47.11 ms | 49.73 ms |
| A 回転 | 23.48 | 22.51 | 90.08 ms | 89.78 ms |
| B 移動 | 23.97 | 22.68 | 65.89 ms | 72.67 ms |
| B 回転 | 25.03 | 25.48 | 57.17 ms | 54.88 ms |
| C 移動 | 39.99 | 40.41 | 29.41 ms | 28.64 ms |
| C 回転 | 28.57 | 28.70 | 79.44 ms | 78.36 ms |

静止は両方式とも3地点で60fps。A=(4480,5504)、B=(4768,5440)、C=(5500,4100)。識別ラベルはkinki／fuji／kanto。fpsは約-5.4～+1.8%の変化で、単回比較のばらつきも含む。

各区間末の遠景保持頂点は、均一間隔71,825～114,075に対し、間引き版50,998～80,561で約29%減った。近景は各地点で残す密度が違い、測定した区間末では135,200に対し122,739～131,505だった。64区画のキャッシュ上限と、表示領域の32区画は維持した。巡回中の遠景候補の切り替えは計5回だった。

CPU時間も一貫して減っていない。例えば区間平均のCPU時間／実時間で、A移動は1.59→1.85コア相当、C移動は1.46→1.66、B回転は1.05→0.98。平坦さの判定・配列の作り直し・遠景の投影誤差判定には追加のCPU処理が必要である。1コア相当はCPU時間1秒／実時間1秒を表し、20論理プロセッサ全体に対する使用率なら20で割る。

| プロセス全体のピーク | 均一間隔（同じ最終実行版） | 間引き版 |
|---|---:|---:|
| Working Set | 1,509.0 MiB | 1,391.0 MiB |
| Private Commit | 3,100.8 MiB | 2,913.6 MiB |

この比較では使用量が低下したが、変更直前に保存した旧実行版の別測定ではWorking Set 1,249.5 MiB、Private Commit 2,673.6 MiBだった。測定間の差が大きく、地形の変更による総RAMの削減率は断定しない。画像・描画先・その他のバッファ・ドライバーも含む使用量であり、頂点削減率からプロセス全体の削減率を推定しない。

生データ：`builds/performance_800/adaptive_after_release.json`、`adaptive_uniform_paired_release.json`、変更直前の `adaptive_before_release.json` と各 `_process.json`。この試行は形状・キャッシュの頂点削減としては動作するが、動作速度の改善を保証するものではない。

## 再生成と比較

標高データを変更したときは、通常の区画を再生成してから今回の資産を作る。元の入力と通常区画のハッシュが一致しない場合、今回の制作ツールは停止する。

```powershell
godot_console --headless --path . --script tools/godot/build_terrain_meshes.gd
godot_console --headless --path . --script tools/godot/build_adaptive_terrain.gd
```

ゲームの起動引数 `-- --uniform-terrain` で元の64区画・均一間隔の地形を使って比較できる。`-- --legacy-terrain` は全国一枚の従来メッシュを使う比較用。通常の起動は今回の間引きを使用する。

主な実装は `scripts/map/terrain_grid_lod.gd`、`map_view_3d.gd`、`terrain_chunk_set.gd`。新資産は `data/derived/elevation/terrain_adaptive_chunks/`。新しい制作処理は `tools/godot/build_adaptive_terrain.gd`。元へ戻す際は、バックアップから変更した既存ファイルを復元してWindows版を再書き出しできる。
